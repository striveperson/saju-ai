# 검증 라운드

검증기는 찾기만 하고 고치지 않는다. 고치는 쪽에는 순서가 없어서,
지적을 받은 자리마다 손을 대면 고친 것이 다음 지적을 낳고 라운드가 끝나지 않는다.

이 스킬은 그 순서다. 상위 규칙은 [docs/06](../../../docs/06-code-working-rules.md) 4장이고,
등급의 정의는 [saju-engine-validator](../../agents/saju-engine-validator.md) 에 있다.

docs/06 이 기록 항목을 모아 두었다가 따로 처리하라고 정했다. 여기가 그 자리다.
평소에는 차단만 고치고 기록은 쌓아 둔다. 쌓인 것을 훑을 때 이 스킬을 부른다.

라운드가 끝나지 않았던 원인은 셋이었다.
고친 것이 낳은 새 기록을 같은 라운드에서 또 고쳤고,
같은 부류인데 지적받은 인스턴스만 고쳤고,
문서 수치를 돌려보지 않고 추론으로 고쳤다.
아래 순서가 그 셋을 각각 막는다.

## 전제

이 스킬을 부른 것이 기록 항목을 고쳐도 좋다는 승인이다.
`saju-validate-gate.sh` 가 평소에 요구하는 "고칠지를 사용자에게 묻는다" 는 여기서 이미 답이 나와 있다.
아래 물음 목록에 걸리는 항목만 그대로 묻는다.

커밋과 push 는 하지 않는다. 라운드가 끝나면 `commit` 스킬로 메시지만 낸다.

## 한 라운드

### 0. 대장을 연다

검증 보고의 기록 항목을 전부 옮겨 번호를 붙인다. 이것이 이번 라운드가 다룰 전부다.

```
| # | 자리 | 무엇이 어긋났나 | 처리 | 어떻게 고치나 |
| - | ---- | --------------- | ---- | ------------- |
| 1 | docs/05:441 | LMT 임계가 어림이다 | 고침 | 23:28 로 바꾼다. 기록 LMT 23:27:52 의 분 절삭값 |
| 2 | daeun.ts:68 | 윤일생 규약이 문서에 없다 | 물음 | |
```

마지막 칸은 `saju-record-fixer` 가 그대로 실행할 지시다. 자리와 바꿀 값이 다 들어 있어야 한다.
값을 비워 두면 실행자가 멈추고 돌려준다.

고치는 중에 눈에 띈 것은 대장에 넣지 않는다. 다음 라운드 몫이다.
대장을 닫아 두는 것이 이 스킬의 핵심이다. 열어 두면 끝나지 않는다.

### 1. 차단부터

차단이 남아 있으면 기록보다 먼저 처리한다.
값이 틀린 채로 문구를 다듬으면 그 수정이 틀린 값 위에 쌓인다.

차단이 물음 목록에 걸리면 거기서 멈추고 답을 기다린다. 기록은 그동안 진행하지 않는다.

### 2. 셋으로 나눈다

물음으로 보내는 것은 이렇다.

- `docs/05` 에 근거 절이 없다. 규칙을 새로 정하는 일이라 도메인 판단이 필요하다
- 루트 CLAUDE.md 유파 표의 네 지점에 걸린다
- 문서와 코드 중 어느 쪽이 틀렸는지가 갈린다
- 고칠 자리가 엔진과 `docs/05` 밖으로 나간다. 다른 문서, 훅, 에이전트 정의, 픽스처 기대값
- `data/` 의 생성 파일이나 일주 앵커를 건드려야 한다

미룸은 이번 변경과 이어지지 않아 별도 작업이 되는 것이다. 대장에 남기고 다음 검증기 호출에 넘긴다.

나머지가 고침이다. 문구가 좁거나 어림인 것, 절 번호와 링크, 중복 상수,
값을 다른 자리가 이미 못 박고 있는 단언 같은 것들이다.

### 3. 실행자에게 넘긴다

고침 항목만 추려 `saju-record-fixer` 에이전트에 넘긴다. 직접 고치지 않는다.
설계를 논한 맥락에서 그대로 고치면 diff 가 대장 밖으로 나간다. 그것이 이 단계를 뗀 이유다.

넘기기 전에 대장의 마지막 칸을 채운다. 실행자는 판단하지 않으므로 지시가 비면 멈춘다.

- 수치와 경계는 돌려서 확인한 값을 적는다. 결론이 되는 값만 보지 말고 그 값을 만드는 중간값도 본다.
  docs/06 1장이다. 문서가 SSOT 라서 어림값 하나가 다음 작업의 근거가 된다
- 같은 부류로 훑을 항목은 부류라고 적는다. 자리 하나만 적으면 그 자리만 고쳐지고
  다음 라운드에 같은 부류가 다시 나온다

돌아온 보고에서 멈춘 항목을 본다. 지시가 모호했으면 다시 적어 넘기고,
새 파일이나 엔진 출력 변경이 필요한 항목이면 물음이나 미룸으로 옮긴다.

### 4. 물음을 한 번에 낸다

항목마다 멈추지 않는다. 고침을 전부 끝낸 뒤 모아서 묻는다.

물음마다 무엇이 갈리는지와 내 권고를 함께 적는다.
선택지만 늘어놓으면 사용자가 판단할 재료가 없다.

### 5. 재검증

기계가 잡는 것을 먼저 털어낸다. 검증기에 보낼 것이 아니다.

```
pnpm --filter web exec vitest run --project saju
pnpm typecheck
pnpm lint
```

그 다음 검증기를 부르고 호출에 셋을 넣는다.

- 이번 라운드에 고친 자리. 에이전트가 범위 확정에 그대로 쓴다
- 미루기로 한 항목 목록. 정의가 "부른 쪽이 미루기로 했다고 알려준 항목은 다시 올리지 않는다" 로 되어 있다
- 이번에 볼 것은 고친 것이 새 차단을 만들지 않았는가다

### 6. 이어갈지 정한다

| 결과                          | 다음                                    |
| ----------------------------- | --------------------------------------- |
| 차단 0, 새 기록 없음          | 끝. 커밋 메시지를 낸다                  |
| 차단 0, 새 기록 있음          | 그 기록으로 다음 라운드 대장을 연다     |
| 차단 있음                     | 다음 라운드를 1번부터 시작한다          |

두 자리에서 멈춘다.

- 라운드가 셋을 넘어간다
- 새 기록 수가 지난 라운드보다 줄지 않는다. 수렴하지 않는다는 뜻이고 더 돌려도 같은 자리를 맴돈다

멈출 때는 남은 항목과 왜 멈췄는지를 적어 사용자에게 넘긴다. 조용히 계속 돌지 않는다.

## 경계

- 지적을 0 으로 만들려 하지 않는다. 차단 0 이 통과다. 기록이 남은 채로 끝나도 된다
- 검증기는 읽기만 하고 실행자는 판단하지 않는다. 무엇을 고칠지 정하는 것은 이 스킬을 도는 쪽이다
- 엔진을 고쳤으면 재검증 없이 라운드를 닫지 않는다. 게이트 훅이 어차피 막지만 순서상으로도 그렇다
