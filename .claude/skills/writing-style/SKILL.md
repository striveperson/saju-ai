# 문장 규칙

규칙의 canonical 목록은 [docs/00-documentation-guide.md](../../../docs/00-documentation-guide.md) 5장이다.
이 스킬은 그 규칙을 실제로 적용하는 방법과 고치기 전후 예시를 담는다.

기계적으로 검사되는 항목(em dash, 이모지, 번호 목록 안의 굵은 강조)은
`.claude/hooks/md-style-guard.sh` 가 저장할 때 잡는다. 여기서는 다루지 않는다.

## 쓰기 전에

무엇을 말할지 정한 다음 문장을 만든다. 문장을 먼저 만들고 내용을 채우면
"다음과 같은 여러 장점이 있습니다" 같은 빈 문장이 생긴다.

## 고치기 전후

### 근거 없는 형용사

강력한, 혁신적인, 원활한, 매끄러운, 최적의, 손쉬운, 견고한.
이런 말은 아무것도 설명하지 않는다. 무엇이 어떻게 되는지로 바꾼다.

```
전  Supabase 는 강력한 인증 기능을 제공하여 원활한 로그인 경험을 만듭니다.
후  Supabase Auth 가 카카오와 Apple 을 공식 공급자로 지원하고 PKCE 흐름이 문서화되어 있다.
```

### 메타 서술

"중요한 점은", "주목할 만한 것은", "다음과 같습니다", "살펴보겠습니다".
읽는 사람은 이미 읽고 있다. 지운다.

```
전  중요한 점은, 다음과 같이 계산과 해석을 분리해야 한다는 것입니다.
후  계산과 해석을 분리한다.
```

### 문장 구조 반복

불릿 전부가 같은 꼴이면 읽는 사람이 항목을 구분하지 못한다.
길이와 구조를 섞는다.

```
전  - 사주팔자를 계산한다
    - 오행 분포를 계산한다
    - 십신 관계를 계산한다
    - 신강약 등급을 계산한다

후  - 생년월일시에서 사주팔자 여덟 글자를 뽑는다
    - 오행 분포와 십신 구성을 낸다
    - 그 둘로 신강약을 판정하고 용신을 정한다
```

### 세 항목 강박

세 개를 채우려고 억지 항목을 넣지 않는다. 두 개면 두 개만 쓴다.

```
전  이 결정은 재현성, 검증 가능성, 그리고 유지보수성을 높입니다.
후  같은 사주에 같은 판정이 나오고, 화면에 근거를 함께 보여줄 수 있다.
```

### 번역투

`~에 대한`, `~를 통해`, `~에 있어서`, `~되어지다`.
우리말 어순으로 고친다.

```
전  이 훅을 통해 엔진의 순수성에 대한 검증이 수행되어집니다.
후  이 훅이 엔진의 순수성을 검사한다.
```

### 단정

결정을 적을 때는 단정한다. `~할 수 있습니다`, `~하는 것이 좋습니다` 를 쓰지 않는다.
확정되지 않은 것은 확정되지 않았다고 명시한다.

```
전  API 라우트를 사용하는 것이 좋을 것 같습니다.
후  서버 호출은 명시적 API 라우트로만 한다.
    (아직 안 정했으면) 야자시 정책 기본값은 아직 정하지 않았다.
```

### 말미 요약

문서 끝에 앞 내용을 되풀이하는 절을 붙이지 않는다.
읽는 사람이 방금 읽은 것을 다시 읽게 만든다.

### 트레이드오프

좋은 점만 쓰지 않는다. 포기한 것을 반드시 함께 적는다.
ADR 의 트레이드오프 절에 장점만 있으면 그 ADR 은 미완성이다.

## 쓰고 나서 확인

- [ ] 형용사를 지웠을 때 문장이 그대로 성립하는가. 성립하면 그 형용사는 장식이었다
- [ ] 불릿의 구조가 서로 다른가
- [ ] "다음과 같습니다" 로 시작하는 문장이 없는가
- [ ] 트레이드오프에 포기한 것이 있는가
- [ ] 끝에 요약 절을 붙이지 않았는가
- [ ] 확정되지 않은 것을 확정된 것처럼 쓰지 않았는가
