# 05. 사주 계산 도메인 규칙

> 사주 계산 로직을 구현하고 검증할 때 참조하는 단일 진실 공급원(SSOT)이다.
> 코드와 이 문서가 어긋나면 코드가 틀린 것으로 간주한다.
> 이 문서가 틀렸다면 근거와 함께 문서를 먼저 고치고 그 다음 코드를 고친다.

구현 위치는 `apps/web/src/lib/saju/` 이며 외부 의존이 없는 순수 함수로 작성한다
([ADR 0001](adr/0001-monorepo-pnpm-workspaces.md), [ADR 0013](adr/0013-saju-engine-purity-enforcement.md)).
검증 케이스는 `apps/web/src/lib/saju/fixtures/cases.ts` 에 두고
`verified: true` 케이스를 회귀 테스트가 실행한다.

지원 연도 범위는 입력 방식에 따라 다르다
([ADR 0014](adr/0014-kasi-data-bundled-not-fetched.md)).

| 입력 | 범위      | 상한의 근거                  |
| ---- | --------- | ---------------------------- |
| 양력 | 1900~2100 | 절기를 계산해 번들한 구간    |
| 음력 | 1900~2050 | KASI 음력 데이터가 덮는 구간 |

범위 밖 입력은 계산하지 않고 거부하며 지원 범위를 안내한다. 근사값으로 대신 계산하지 않는다.

## 1. 60갑자 기본

- 천간(天干) 10개: 갑(甲) 을(乙) 병(丙) 정(丁) 무(戊) 기(己) 경(庚) 신(辛) 임(壬) 계(癸)
- 지지(地支) 12개: 자(子) 축(丑) 인(寅) 묘(卯) 진(辰) 사(巳) 오(午) 미(未) 신(申) 유(酉) 술(戌) 해(亥)
- 60갑자 인덱스: 갑자가 0, 을축이 1, 계해가 59 인 순환.
- 천간 음양: 갑·병·무·경·임이 양(陽), 을·정·기·신·계가 음(陰).
- 천간 오행: 갑을 목, 병정 화, 무기 토, 경신 금, 임계 수.
- 지지 오행: 인묘 목, 사오 화, 진술축미 토, 신유 금, 해자 수.

### 1.1 지장간(支藏干)

지지 안에 숨은 천간이다. 여기(餘氣), 중기(中氣), 본기(本氣) 순으로 놓는다.
본기 오행은 위의 지지 오행과 같다. 11장의 득령·득지·득시와 통근 판정이 이 표를 쓴다.

| 지지 | 여기 | 중기 | 본기 |
| ---- | ---- | ---- | ---- |
| 자   | 임   |      | 계   |
| 축   | 계   | 신   | 기   |
| 인   | 무   | 병   | 갑   |
| 묘   | 갑   |      | 을   |
| 진   | 을   | 계   | 무   |
| 사   | 무   | 경   | 병   |
| 오   | 병   | 기   | 정   |
| 미   | 정   | 을   | 기   |
| 신   | 무   | 임   | 경   |
| 유   | 경   |      | 신   |
| 술   | 신   | 정   | 무   |
| 해   | 무   | 갑   | 임   |

출처는 [정해 만세력 11강](https://doc.8-codes.com/docs/lecture/11/) 과
[사주명리 입문의 월률분야 항목](https://www.sajustudy.com/133) 이고 두 곳이 12지지 전부에서 일치한다.
선행 저장소 `/Users/mychoi/f-lab/saju` 의 `core/tables.ts` 가 쓰던 표와도 같다.

계통이 둘이다. 위 표는 월률분야(月律分野)이고, 인원용사(人元用事) 계통은
왕지(자·묘·오·유)와 해에서 여기를 뺀다.
자는 계, 묘는 을, 유는 신 하나씩이고 오는 기·정, 해는 갑·임이다.
한국 명리 실무의 표준인 월률분야를 채택한다.

오행으로 환산하면 두 계통이 실제로 갈리는 곳은 하나뿐이다.
자의 임계는 둘 다 수이고 묘의 갑을은 목, 유의 경신은 금, 오는 양쪽 다 화와 토를 갖는다.
해(亥)에 무토가 들어가는가만 11.5 의 통근 판정을 가른다.

갈리는 자리가 하나라는 것이 영향이 없다는 뜻은 아니다.
일간이 수인 신강 사주에서 토가 해의 여기로만 존재하면 월률분야는 관성 유근이라 극제로 가고
인원용사는 무근이라 식상 대체로 간다. 용신이 바뀐다.
지금 옵션으로 열지 않는 것은 가르는 검증 케이스가 아직 없기 때문이며
그런 케이스를 확보하면 그때 이 한 지점만 열면 된다.

일수(여기 10일, 본기 20일 등)는 싣지 않는다.
[ADR 0007](adr/0007-strength-five-grade-model.md) 이 지장간 가중 세력 계산을 기각해 쓰이지 않고,
오의 중기와 본기 일수는 출처마다 갈린다.

## 2. 년주(年柱)

년주 경계는 입춘 절입 시각이며 분 단위로 판정한다. 양력 1월 1일도 아니고 음력 설날도 아니다.
입춘 절입 시각 이전 출생이면 전년도 년주를 쓴다.

앵커 값을 이 문서에 하드코딩하지 않는다. 일주와 같은 규율을 따른다.
구현은 `pillars.ts` 이고 `pillars.test.ts` 가 `verified` 케이스로 그 값을 다시 검증한다.

앵커의 근거는 KASI 음양력 API 의 세차다. 세차는 음력 설날 기준이라 이 문서의 입춘 기준과
다르지만, 입춘과 설날 사이 구간을 벗어나면 두 기준이 같은 값을 낸다.
그 구간 밖의 날짜로만 대조한다.

## 3. 월주(月柱)

월 경계를 만드는 것은 12절(節)이다. 12중기(中氣: 우수, 춘분 등)는 월 경계와 무관하다.

| 월지(月支) | 절기 시작  | 대략 양력 |
| ---------- | ---------- | --------- |
| 인(寅)     | 입춘(立春) | 2/4경     |
| 묘(卯)     | 경칩(驚蟄) | 3/6경     |
| 진(辰)     | 청명(淸明) | 4/5경     |
| 사(巳)     | 입하(立夏) | 5/6경     |
| 오(午)     | 망종(芒種) | 6/6경     |
| 미(未)     | 소서(小暑) | 7/7경     |
| 신(申)     | 입추(立秋) | 8/8경     |
| 유(酉)     | 백로(白露) | 9/8경     |
| 술(戌)     | 한로(寒露) | 10/8경    |
| 해(亥)     | 입동(立冬) | 11/7경    |
| 자(子)     | 대설(大雪) | 12/7경    |
| 축(丑)     | 소한(小寒) | 1/6경     |

"대략 양력"은 참고용이다. 실제 판정은 반드시 `data/solar-terms.ts` 의 절입 시각으로 한다.
그 값은 태양 겉보기 황경이 15도의 배수가 되는 순간을 계산한 것이고,
2000~2028 은 KASI 발표값과 교차검증되어 있다([ADR 0014](adr/0014-kasi-data-bundled-not-fetched.md)).

### 3.1 월두법(月頭法, 오호둔 五虎遁)

년간에서 인월(정월)의 월간을 정한다.

| 년간          | 인월(정월) 월주 |
| ------------- | --------------- |
| 갑(甲)·기(己) | 병인(丙寅)      |
| 을(乙)·경(庚) | 무인(戊寅)      |
| 병(丙)·신(辛) | 경인(庚寅)      |
| 정(丁)·임(壬) | 임인(壬寅)      |
| 무(戊)·계(癸) | 갑인(甲寅)      |

이후 월은 60갑자 순서로 진행한다.

구현은 `pillars.ts` 이고 위 두 표를 그대로 encode 한다.
표에 독립 출처가 없어서, 구현이 표를 잘못 옮겼는지는 테스트가 잡지만
표 자체가 틀렸는지는 잡지 못한다. 검증 케이스에도 그 사실을 적어 둔다.

## 4. 일주(日柱)

율리우스 적일을 60으로 나눈 나머지로 계산한다. 절기와 무관하다.

앵커 값을 이 문서에 하드코딩하지 않는다.
`fixtures/cases.ts` 에서 공인 만세력 대조로 `verified: true` 처리된
케이스 3개 이상으로 확정한다.

구현은 `pillars.ts` 이고 앵커 상수는 거기 있다.
`pillars.test.ts` 가 verified 케이스로 그 값을 다시 검증하므로,
상수가 하나만 어긋나도 테스트가 실패한다.

자시 경계(23시)의 날짜 귀속은 6장 야자시 정책을 따른다.
계산은 보정이 끝난 시각을 받는다. 보정 순서는 7장 파이프라인이다.

## 5. 시주(時柱)

### 5.1 시지(時支) 구간

진태양시 보정을 적용한 뒤의 시각을 기준으로 판정한다.

자(23-01), 축(01-03), 인(03-05), 묘(05-07), 진(07-09), 사(09-11),
오(11-13), 미(13-15), 신(15-17), 유(17-19), 술(19-21), 해(21-23)

### 5.2 시두법(時頭法, 오서둔 五鼠遁)

일간에서 자시의 시간(時干)을 정한다.

| 일간          | 자시(子時) 시주 |
| ------------- | --------------- |
| 갑(甲)·기(己) | 갑자(甲子)      |
| 을(乙)·경(庚) | 병자(丙子)      |
| 병(丙)·신(辛) | 무자(戊子)      |
| 정(丁)·임(壬) | 경자(庚子)      |
| 무(戊)·계(癸) | 임자(壬子)      |

자시부터 60갑자 순서로 진행해 그날의 열두 시주가 나온다.

기준이 되는 일간은 자시가 속한 날의 일간이며 6장의 야자시 정책과 무관하다.
보정 후 23:00~23:59 출생이면 야자시설을 택해도 시간은 다음날 일간에서 뽑는다.

그래서 야자시설에서는 일주의 일간과 시주가 이 표를 어긋난다.
예를 들어 병인일 23:30 출생은 일주가 병인이고 시주가 경자인데,
병 일간의 자시는 무자이므로 표와 맞지 않는다.
구현 오류가 아니라 야자시설의 성질이고, 야자시설을 비판하는 논거가 정확히 이것이다.

근거는 셋이다.

- `expected.hour` 가 채워진 verified 케이스가 전부 이 규칙으로 재현된다.
  청목서원 명리보감과 플러스만세력, 포스텔러 대조로 확정한 값들이다.
  다만 대부분은 자시가 아니거나 조자시라 두 정책이 애초에 갈리지 않는다.
  기준 일간을 가르는 것은 보정 후 23시대로 넘어가는 케이스뿐이다.
- 그 케이스 넷을 야자시를 켜고 조회했다(2026-08-09, 포스텔러).
  1988-09-05 00:50 서울은 일주가 계해에서 임술로 바뀌는데 시주는 임자 그대로고,
  2005-05-10 00:20 부산은 갑오에서 계사로 바뀌는데 시주는 갑자 그대로다.
  자시 경계 케이스 둘도 일주만 을해에서 갑술로 바뀌고 시주는 병자 그대로다.
  전부 바뀐 일간으로는 나올 수 없는 시주다.
- 위의 병인일 경자시 논거다.
  [초코서당](https://chocosd.com/3441/)의 야자시설 비판에서 가져왔다.

## 6. 야자시(夜子時)와 조자시(朝子時)

23:00~24:00 출생의 일주 귀속은 유파가 갈린다.

- 정자시설(正子時說): 23시부터 다음날로 본다. 일주가 다음날 간지가 된다.
- 야자시설(夜子時說): 자정까지는 당일 일주를 유지하고 시주만 자시로 잡는다.
  00:00~01:00 은 조자시(朝子時)로 그날 일주다.

단일 정답을 강요하지 않고 설정 옵션으로 제공한다.
기본값은 제품 결정 사항이며, 어떤 값을 택하든 결과 화면에 적용된 방식을 명시한다.

코드 대응(`SajuOptions.ziPolicy`): 야자시설이 `sameDay`, 정자시설이 `nextDay` 다.
검증 케이스 JSON 의 `night_zi_policy` 는 `ye` 가 `sameDay`, `zheng` 이 `nextDay` 에 대응한다.

## 7. 시간 보정 파이프라인

입력 시각에 아래 순서로 보정을 적용한 뒤 시지를 판정한다.

1. 표준시 이력 정규화
2. 서머타임 해제
3. 진태양시 보정

정규화의 기준은 UTC+9 다. 1단계와 2단계는 개념이 둘이지만 산술로는 한 번의 덧셈이다.
기록된 벽시계를 당시 실제 오프셋으로 빼서 물리적 시각을 얻고, 거기에 540분을 더하면 둘이 함께 끝난다.
서머타임을 별도 단계에서 다시 빼면 한 시간이 이중으로 적용된다.

이 장의 값은 tz database `Asia/Seoul` 에서 왔다.
근거와 조달 방식은 [ADR 0015](adr/0015-korea-time-history-bundled.md) 이고,
기계가 뜬 정답지가 `apps/web/src/lib/saju/fixtures/tzdb-asia-seoul.json` 이다.

### 7.1 한국 표준시 이력

전환은 1900~2100 구간에 29번 있다. 그중 오프셋이 바뀌는 것은 아래 다섯이다.

| 전환 순간 (UTC)     | 이후 표준시 | 현지 시계가 겪는 일                     |
| ------------------- | ----------- | --------------------------------------- |
| (1900년 초부터)     | UTC+8:27:52 | 표준시 이전. 서울의 지방평균태양시다    |
| 1908-03-31 15:32:08 | UTC+8:30    | 03-31 24:00 다음이 04-01 00:02:08 이다  |
| 1911-12-31 15:30:00 | UTC+9:00    | 12-31 24:00 다음이 01-01 00:30 이다     |
| 1954-03-20 15:00:00 | UTC+8:30    | 03-20 24:00 다음이 같은 날 23:30 이다   |
| 1961-08-09 15:30:00 | UTC+9:00    | 08-09 24:00 다음이 08-10 00:30 이다     |

1945-09-07 에 약칭이 JST 에서 KST 로 바뀌지만 오프셋은 UTC+9 로 같다. 판정에 영향이 없다.

1908년 4월 이전은 한국에 표준시가 없었다. 그 구간은 tz database 를 따라 UTC+8:27:52 로 해석하고,
당시 기록된 시각이 어느 시계를 본 것인지 알 수 없다는 사실을 결과 화면에 표시한다.

구현 노트: 표준시를 UTC 오프셋 이동으로 정규화하는 대신,
해당 날짜의 표준 자오선 이력(UTC+8:30 시기가 127.5도, 그 외가 135도)을
진태양시 보정식에 반영하는 방식으로 같은 효과를 낼 수 있다.
두 방식은 시지 판정에 대해 동등하다. `127.5 × 4 = 510` 이고 `135 × 4 = 540` 이라
두 계산이 같은 지방평균태양시로 수렴하기 때문이다.

**두 방식을 함께 쓰면 30분이 이중으로 적용된다.**
UTC+9 로 정규화한 뒤에는 시대별 표준 자오선 표를 두지 않고 자오선을 135도 하나로 고정한다.

이 동등성은 공인 만세력 두 곳의 출력으로 확인했다.
청목서원 명리보감은 UTC+8:30 시기의 경도 보정치를 서울 -2분, 부산 +6분으로 준다.
플러스만세력은 자시 23:30 시간표에 도시별 보정(서울 -2분 06초, 부산 +6분 18초)을 더하는 방식이다.
둘 다 UTC+9 정규화 뒤 `(경도 - 135) × 4` 와 같은 값에 도달한다.
검증 케이스는 `fixtures/cases.ts` 의 `verified-19550808-seoul` 과 `verified-19560707-busan` 이다.

경도 보정을 하지 않는 무보정 관행은 기록된 시계를 그대로 쓰므로 이 구간에서 30분이 갈린다.
그 경로는 검증된 적이 없어 제품에서 제외했다. ADR 0016 이 근거다.

### 7.2 서머타임(일광절약시간)

12번 시행되었다. 아래는 현지 벽시계 기준이며, 종료 시각은 시계를 되돌리기 직전의 값이다.

| 연도 | 시작             | 종료             | 시행 중 오프셋 |
| ---- | ---------------- | ---------------- | -------------- |
| 1948 | 06-01 01:00      | 09-13 00:00      | UTC+10:00      |
| 1949 | 04-03 01:00      | 09-11 00:00      | UTC+10:00      |
| 1950 | 04-01 01:00      | 09-10 00:00      | UTC+10:00      |
| 1951 | 05-06 01:00      | 09-09 00:00      | UTC+10:00      |
| 1955 | 05-05 01:00      | 09-09 00:00      | UTC+9:30       |
| 1956 | 05-20 01:00      | 09-30 00:00      | UTC+9:30       |
| 1957 | 05-05 01:00      | 09-22 00:00      | UTC+9:30       |
| 1958 | 05-04 01:00      | 09-21 00:00      | UTC+9:30       |
| 1959 | 05-03 01:00      | 09-20 00:00      | UTC+9:30       |
| 1960 | 05-01 01:00      | 09-18 00:00      | UTC+9:30       |

UTC+10:00 인 다른 해와 다르므로 한 시간을 일괄로 빼면 틀린다.

1988년 이후로 시행된 적이 없다.

### 7.3 진태양시 보정

- 옵션이 아니라 항상 적용한다([ADR 0016](adr/0016-true-solar-time-always-applied.md)).
  끄는 경로는 공인 만세력 대조 사례를 찾지 못해 검증된 적이 없다.
- 평균태양시 보정은 `(출생지 경도 - 당시 표준 자오선) × 4분/도` 다.
  자오선 135도 기준으로 서울(126.98°E)은 약 -32분, 부산(129.08°E)은 약 -24분이다.
- 7.1 의 정규화를 마친 시각에 적용하므로 자오선은 시대와 무관하게 135도다.
  적용할 값은 `(경도 - 135) × 4` 분이다.
- 경도 입력이 원칙이다.
  보정을 끌 수 없으므로 경도를 모르면 -30분(서울 관례값) 폴백이 반드시 쓰인다.
  폴백을 썼다는 사실을 화면에 명시한다.
  이 값은 자오선 127.5도와 같은 말이며(`(127.5 - 135) × 4 = -30`),
  UTC+8:30 시기의 30분은 이미 정규화가 처리했으므로 시대별로 조정하지 않는다.
  -30분 고정만 제공하고 경도 입력이 불가능한 구현은 오류로 본다.
- 균시차(均時差, equation of time, 연중 약 ±15분 변동) 반영은 추가 옵션이다(유파 선택).
  아직 구현하지 않았다.
- 진태양시는 시지 판정에만 쓴다. 절기 경계 판정에는 적용하지 않는다.
  절입은 지구 전체에 하나인 천문 순간이라 출생 순간과 물리적 시각으로 비교한다.
  그래서 년주와 월주 계산은 보정된 벽시계가 아니라 물리적 시각을 인자로 받는다.

### 7.4 존재하지 않는 벽시계와 두 번 존재하는 벽시계

시계를 앞으로 돌리면 그 사이 벽시계가 존재하지 않고, 뒤로 돌리면 두 번 존재한다.
1900~2100 구간에 28개가 있다.

존재하지 않는 구간 15개.

```
1908-04-01 00:00~00:02:08    1912-01-01 00:00~00:30    1961-08-10 00:00~00:30
1948-06-01 00:00~01:00       1949-04-03 00:00~01:00    1950-04-01 00:00~01:00
1951-05-06 00:00~01:00       1955-05-05 00:00~01:00    1956-05-20 00:00~01:00
1957-05-05 00:00~01:00       1958-05-04 00:00~01:00    1959-05-03 00:00~01:00
1960-05-01 00:00~01:00       1987-05-10 02:00~03:00    1988-05-08 02:00~03:00
```

두 번 존재하는 구간 13개.

```
1948-09-12 23:00~24:00       1949-09-10 23:00~24:00    1950-09-09 23:00~24:00
1951-09-08 23:00~24:00       1954-03-20 23:30~24:00    1955-09-08 23:00~24:00
1956-09-29 23:00~24:00       1957-09-21 23:00~24:00    1958-09-20 23:00~24:00
1959-09-19 23:00~24:00       1960-09-17 23:00~24:00    1987-10-11 02:00~03:00
1988-10-09 02:00~03:00
```

1988년 이전 전환이 전부 자정에 걸려 있어 **28개 중 24개가 자시 구간(23:00~01:00) 안에 있다.**
6장의 야자시 정책과 정확히 겹치는 자리이고, 해석이 갈리면 시지와 일주가 함께 갈린다.
1958-09-20 23:15 이 그런 경우다. 앞의 해석이면 해시에 20일 일주, 뒤의 해석이면 자시에 21일 일주다.

기본 해석은 이렇다.

- 두 번 존재하면 앞의 것을 쓴다. 전환 전 오프셋으로 읽는다
- 존재하지 않으면 전환 직후로 민다

조용히 고르지 않는다. 고르지 않은 쪽의 시각도 함께 반환하고,
기본값으로 고른 것인지 사용자 입력에 따라 고른 것인지 구분해 결과 화면에 표시한다.

계산을 거부하지는 않는다. 지원 범위 밖은 답이 없는 경우지만 여기는 답이 둘인 경우다.

### 7.5 서머타임 기록 여부

병원 출생 기록이 서머타임 적용 시각인지 알 수 없는 경우가 많다.
기록의 성격을 입력으로 받는다. 값은 셋이다.

| 값         | 뜻                                              |
| ---------- | ----------------------------------------------- |
| `daylight` | 기록이 서머타임 시계 그대로다                   |
| `standard` | 기록자가 표준시로 환산해 적었다                 |
| `unknown`  | 모른다. 기본값이다                              |

`unknown` 은 당시 법적 시계, 즉 `daylight` 와 같은 값으로 계산한다.
1987년 7월에 걸린 시계는 서머타임 시계였고, 기록자가 환산했으리라 볼 근거가 없기 때문이다.
다만 사용자가 확인해 준 값과 우리가 가정한 값은 구분해서 남기고,
서머타임 시행 구간에 걸린 출생에는 그 사실을 화면에 표시한다.

`standard` 를 고르면 서머타임 전환이 만든 이상 구간 24개가 사라진다.
기준 오프셋 프레임으로 읽으므로 전환 자체를 지나가지 않기 때문이다.

## 8. 음력 입력 처리

- 사주 판정 자체는 절기(양력 태양 위치) 기준이므로 음력은 입력 편의 기능일 뿐이다.
- 음력에서 양력으로의 변환은 KASI 공식 데이터를 기준으로 한다.
  윤달(閏月) 여부 플래그를 입력받아야 한다.
  같은 "음력 4월 10일"이 평달과 윤달로 두 번 존재할 수 있다.
- 자체 음력 산출 알고리즘을 구현하지 않는다.
  한국 음력은 천문 계산과 관습 규칙이 섞여 있어 공식 데이터 대조 없이는 오차가 난다.

## 9. 대운(大運)

1. 방향: 년간이 양이고 남자이거나, 년간이 음이고 여자면 순행(順行)이다. 반대 조합이면 역행(逆行)이다.
2. 대운수(첫 대운 나이): 출생 시각부터 순행이면 다음 절입까지, 역행이면 직전 절입까지의 시간을 계산해
   3일을 1년으로 환산하고 연 단위 몫을 쓴다. 나머지를 개월이나 일로 올려 대운수를 키우지 않는다.
   경계는 12절이며 중기는 세지 않는다. 3장의 월 경계와 같은 표다.
   출생 시각이 절입 순간과 같으면 그 절입은 이미 지난 것으로 본다. 3장의 월 경계 판정과 같은 방향이다.
   그래서 절입 순간 출생은 역행 대운수가 0 이고 순행은 다음 절입까지의 몫이 된다.
   같은 출생이 성별로 0 과 10 까지 갈리는 자리다.
3. 대운 간지: 월주의 다음 간지에서 시작해 순행이나 역행 방향으로 60갑자를 진행한다.
   월주 자체는 원국이므로 첫 대운이 아니다. 10년 단위로 10개를 낸다.
4. 나이 표기: 대운과 세운 나이는 만 나이로 표시한다.
   첫 대운 나이는 기운(起運)까지 경과한 만 연수(정밀 환산의 연 단위 몫)이고 이후 대운마다 10을 더한다.
   만세력 라이브러리가 세는나이를 반환하면 그대로 쓰지 않고 변환한다.
   화면에는 만 나이임을 병기한다.
5. 세운(歲運): 그 해의 간지이고 2장의 년주와 같은 규칙이다. 경계가 입춘이지 1월 1일이 아니다.
   대운 하나가 덮는 열 해의 세운을 그 대운 안에 중첩한다.
   열 해의 축은 만 나이이며 대운 시작 나이에서 1씩 늘어난다.
   각 해의 사주 연도는 그 나이가 되는 생일의 사주 연도다.
   대운 시작 연도도 같은 규칙의 첫 해다.
   출생 사주 연도나 대운 시작 연도에 나이를 더하는 산술로 대신하지 않는다. 이유는 9.7 에 있다.

### 9.6 대운수 나머지를 버리는 이유

3일을 1년으로 환산하면 대개 나머지가 남는다. 1일을 4개월로, 1시간을 5일로 더 내려가는 유파가 있다.
그 환산은 기운 시각을 정밀하게 잡을 때 쓰이는 것이고 대운수 자체를 올리지는 않는다.
4항이 첫 대운 나이를 연 단위 몫으로 이미 정했으므로 두 규칙이 갈릴 자리가 없다.

옵션으로 열어 두지 않는 이유는 가르는 검증 케이스가 없기 때문이다.
기준 케이스는 7.14년, 앵커 케이스는 4.16년이라 버림과 반올림이 같은 값을 낸다.
근거 없이 다른 값을 내는 경로를 제품에 남기지 않는다는 [ADR 0016](adr/0016-true-solar-time-always-applied.md) 의 기준을 여기에도 적용한다.
나머지가 2일을 넘는 검증 케이스를 확보하면 그때 다시 판단한다.

### 9.7 대운이 시작하는 사주 연도를 생일에서 얻는 이유

출생 사주 연도에 나이를 더하는 산술이 더 간단하지만 입춘 경계에서 한 해 밀린다.
입춘 절입 시각이 해마다 하루 가까이 흔들리기 때문이다.

입춘 직전에 태어난 사람은 사주 연도가 전년도다. 그 사람이 만 N세가 되는 순간은
생일이므로 그 해 입춘보다 뒤일 수 있고, 그러면 실제 사주 연도가 산술값보다 하나 크다.
1901년 입춘 1분 전 출생에 대운수 4 를 대입하면 산술은 1904 를 내지만
만 4세가 되는 1905-02-04 는 그 해 입춘을 이미 지나 1905년이다.
1901년부터 2090년까지 입춘 1분 전 출생과 대운수 1에서 10까지를 짝지은 1900개 중
1087개가 어긋난다. 세운 열 해가 통째로 한 칸 밀리므로 조용히 틀리는 유형이다.

생일 순간을 2장의 사주 연도 판정에 그대로 넣으면 이 문제가 사라진다.
새 상수가 필요 없고 "만 N세가 되는 해" 라는 문장이 화면에도 그대로 쓰인다.

세운 열 해도 같은 방법으로 얻는다. 대운 시작 연도만 생일에서 얻고 나머지 아홉 해를
1씩 더하면 같은 어긋남이 한 단계 아래에서 되풀이되기 때문이다.
나이를 축으로 두고 해마다 그 나이가 되는 생일을 판정한다.

입춘 시각이 흔들리므로 인접한 두 해의 사주 연도가 같거나 한 해를 건너뛸 수 있다.
한 사주 연도 안에 생일이 두 번 들거나 한 번도 들지 않는 경우이고 정의의 결과다.
나이가 축이므로 대운 열 개의 나이는 빈틈없이 이어진다.
연도를 축으로 삼으면 이 어긋남이 대운과 대운 사이로 옮겨가 겹치는 해나 빈 해가 생긴다.

생일의 날짜는 7.1 의 정규화 프레임에서 읽는다. 출생 순간을 UTC+9 벽시계로 되돌린 날짜이고
표준시 이력을 다시 보지 않는다. 일주와 시주가 같은 프레임에서 나오므로 엔진이 한 프레임을 쓴다.

이 선택이 드러나는 구간이 있다. 표준시가 UTC+8:30 이던 1908~1911 과 1954~1961 에
현지 시각 23:30 이후에 태어나면 정규화 날짜가 기록 날짜보다 하루 뒤다. 그 하루가 생일이 되고,
생일이 입춘에 붙어 있으면 세운 열 해의 연도가 한 칸 옮겨간다.
기록 날짜를 생일로 쓰려면 해마다 그 날짜의 오프셋을 다시 찾아야 하고 원국과 프레임이 갈린다.
그렇게 하지 않는다.

기운(起運) 순간 자체는 생일이 아니다. 출생 시각에 정밀 연수를 더한 시점이고
대운수의 소수부만큼 생일보다 뒤에 온다. 그 순간을 구하려면 1년을 며칠로 볼지
정해야 하는데 이 문서에 근거가 없다. 지금은 아무도 그 값을 쓰지 않으므로 계산하지 않는다.
필요해지면 그때 정한다.

### 9.8 지원 범위를 넘는 대운 연도

입력 지원 범위는 양력 1900~2100 이지만 대운은 출생에서 100년 뒤까지 뻗는다.
대운수는 0에서 10 사이다. 상한은 2항의 규칙이 아니라 절기 데이터의 성질에서 나온다.
연속한 두 12절의 간격이 가장 넓은 값이 31.44일이고 망종에서 소서까지의 구간이다.
1900년, 1901년, 1904년 셋이 같은 값으로 가장 넓다.
3일을 1년으로 환산하면 10.48 이라 몫이 10 을 넘지 못한다.
따라서 마지막 대운의 시작 나이는 90에서 100 이고
마지막 세운의 나이는 그보다 아홉 해 뒤인 99에서 109 다.
그래서 대운 시작 연도는 2001년 이후 출생부터, 세운 연도는 1992년 이후 출생부터
대운수에 따라 절기 데이터 밖으로 나간다.

그 연도는 판정하지 않고 비운다. 입력은 거부하지 않는다.
머리말의 "범위 밖 입력은 계산하지 않고 거부한다" 는 입력에 대한 규칙이고
여기는 지원 범위 안의 입력이 만들어 내는 출력이다.
1992년생에게 사주를 못 낸다고 답할 이유가 없다.

대운 간지와 나이는 그대로 낸다. 대운 간지는 월주에서 60갑자를 진행한 값이고
나이는 첫 대운 나이에 10을 더해 가는 값이라 절기 데이터를 보지 않는다.
세운 간지는 그 해 사주 연도의 년주라 연도와 함께 빈다.
그 해가 어느 사주 연도인지만 입춘 절입 시각을 알아야 정해진다.
데이터 없이 답하려면 입춘이 늘 같은 날짜 폭에 놓인다는 전제가 필요한데
그 폭은 1900~2100 에서 확인한 것이라 밖에 적용할 근거가 없다.
2100년이 윤년이 아니라 직후의 절입 날짜가 밀리는 것도 그 전제를 흔든다.

하한도 같은 이유로 비운다. 1900년 입춘 이전은 절기 배열 안이지만 판정 경계인
1899년 입춘이 데이터에 없어 그 순간이 어느 사주 연도인지 정할 수 없다.
대운과 세운은 생일이 출생보다 앞설 수 없어 이 구간에 닿지 않는다.

원국은 다르다. 1900년 1월 1일부터 그 해 입춘 전까지의 출생은 년주부터 거부된다.
머리말의 지원 범위 표가 1900~2100 이라 표와 어긋나는 34일이 있는 셈이다.
절기 데이터를 1899년까지 한 해 늘리면 사라지지만 지금은 거부한다.

절기 데이터를 늘리는 것은 해결이 아니다.
값의 출처인 `de440s.bsp` 가 2150-01-21 까지만 덮어 2050년 이후 출생이 그대로 남는다.

데이터 상한에 바로 붙은 구간은 아직 정하지 않았다. 알려진 것이 둘이다.

2100년 대설(12월 7일) 이후 출생은 대운수 계산이 거부된다. 다음 절인 2101년 소한이
데이터에 없기 때문이다. 역행이면 직전 절만 있으면 되는데 구현이 앞뒤를 함께 요구해
순행과 역행이 같이 막힌다. 이 구간을 정할 때 그 둘을 갈라야 한다.

2100년 동지(12월 22일) 이후의 생일은 사주 연도가 비운다. 그 해 입춘이 데이터에 있어
연도가 2100 으로 정해지는데도 절기 배열 밖이라 판정에 이르지 못한다.
지금 실제로 도달한다. 1993년 12월생의 마지막 세운이 여기 걸린다.

둘 다 2100년이 가까워야 입력 자체가 생기므로 그전에 절기 데이터를 갱신하고
그때 함께 정한다.

## 11. 신강약(身强弱)과 억부용신(抑扶用神)

신강약 백분율과 용신 분기는 업계 표준이 없는 정량화 모델이므로 이 앱의 결정을 여기에 기록한다.
5단계 4요소 모델을 쓴다([ADR 0007](adr/0007-strength-five-grade-model.md)).

구현은 `apps/web/src/lib/saju/strength.ts` 이고 가중치와 임계값은 설정 상수로 노출한다.

### 11.1 입력

만세력 계산이 산출한 사주팔자(년월일시 각 천간과 지지)와 일간.
강약 판정은 만세력 계산과 분리된 순수 함수로 구현한다.

### 11.2 십성 관계 분류

일간 오행을 기준으로 다섯으로 나눈다.

| 분류 | 관계               |
| ---- | ------------------ |
| 비겁 | 일간과 같은 오행   |
| 인성 | 일간을 생하는 오행 |
| 식상 | 일간이 생하는 오행 |
| 재성 | 일간이 극하는 오행 |
| 관성 | 일간을 극하는 오행 |

지원 세력은 비겁과 인성의 합이다.

### 11.3 판정 요소 네 가지

| 요소       | 정의                                             |
| ---------- | ------------------------------------------------ |
| 득령(得令) | 월지 본기 오행이 지원 세력                       |
| 득지(得地) | 일지 본기 오행이 지원 세력                       |
| 득시(得時) | 시지 본기 오행이 지원 세력                       |
| 득세(得勢) | 일간을 제외한 7글자 중 지원 세력 글자가 4개 이상 |

본기는 1.1 의 지장간 표에서 읽는다. 본기 오행은 지지 오행과 같으므로 결과는 1장 목록과 같다.

유파 옵션: 득령·득지·득시를 비겁만으로 좁히는 유파가 있다.
`supportIncludesResource` 설정으로 제어하며 기본값은 true 다.
이 옵션은 세 요소에만 걸린다. 득세, 11.4 의 태약 특례가 세는 지원 글자 수,
11.6 의 `supportRatio` 는 셋 다 11.2 의 정의를 그대로 쓴다.

적용한 값은 결과에 담아 화면이 표시할 수 있게 한다. 11.6 의 `applied` 다.

### 11.4 등급 산출

1. 네 요소가 모두 참이면 태강(太强)이다.
2. 네 요소가 모두 거짓이고 지원 글자 수(일간 제외)가 1개 이하면 태약(太弱)이다.
3. 그 외에는 가중 점수로 판정한다. `score = 득령×2.0 + 득지×1.0 + 득시×0.5 + 득세×1.5` 이고 만점은 5.0 이다.

| score             | 등급       |
| ----------------- | ---------- |
| 3.0 이상          | 신강(身强) |
| 1.5 이상 3.0 미만 | 중화(中和) |
| 1.5 미만          | 신약(身弱) |

가중치와 임계값은 전부 설정으로 노출한다.
기본값은 11.7 의 검증 케이스를 재현하도록 잡은 것이며 verified 케이스가 늘어나면 재보정한다.
월령 가중(득령 2.0)이 가장 크다는 원칙만 유지한다.

### 11.5 용신 분기

| 등급 | 1순위          | 2순위 | 비고                                                                                               |
| ---- | -------------- | ----- | -------------------------------------------------------------------------------------------------- |
| 태강 | 식상(설기洩氣) | 재성  | 왕신충발(旺神沖發) 회피. 관성 극제는 후순위. 원국에 식상이 0퍼센트여도 결핍 보충 관점에서 선택한다 |
| 신강 | 관성(극제剋制) | 재성  | 관성이 지장간 포함 무근(無根)이고 식상이 유근이면 식상으로 대체하고 사유를 결과에 표기한다         |
| 중화 | 억부 불필요    | 없음  | `needsJohuReview` 플래그를 올려 조후나 병약 등 다른 용신법 검토로 넘긴다                           |
| 신약 | 인성(생조生助) | 비겁  |                                                                                                    |
| 태약 | 인성           | 비겁  | `considerJongGyeok` 플래그. 지원 세력이 사실상 없으면 종격(從格) 검토                              |

통근(通根) 판정: 해당 오행이 네 지지의 지장간(여기, 중기, 본기 전부) 어디에든 존재하면 유근이다.
지장간은 1.1 의 표를 쓴다.

신강에서 1순위가 식상으로 대체되어도 2순위는 재성 그대로다.
바뀌는 것은 1순위와 그 사유 표기뿐이다.

태강이면서 식상, 재성, 관성이 모두 부재하면 `considerJeonWangGyeok`(전왕격, 종왕격) 플래그를 올린다.

### 11.6 출력 형식

```ts
// apps/web/src/lib/saju/strength.ts
type StrengthResult = {
  grade: '태강' | '신강' | '중화' | '신약' | '태약';
  flags: {
    deukRyeong: boolean;
    deukJi: boolean;
    deukSi: boolean;
    deukSe: boolean;
  };
  score: number;
  supportRatio: number; // 일간 포함 8글자 균등(각 12.5%) 기준 지원 비율
  elementDistribution: Record<Element, { count: number; ratio: number }>;
  yongshin: { element: Element; method: string; fallbackReason?: string } | null;
  huisin: Element | null; // 희신(2순위)
  flags2: {
    needsJohuReview: boolean;
    considerJongGyeok: boolean;
    considerJeonWangGyeok: boolean;
  };
  applied: { supportIncludesResource: boolean }; // 적용한 유파 값
};
```

`applied` 를 두는 이유는 이 값이 결과를 실제로 가르기 때문이다.
11.7 의 기준 케이스는 false 로 두면 태강에서 신강으로, 용신이 금에서 목으로 바뀐다.
어떤 값을 적용했는지 화면에 표시한다는 것이 루트 CLAUDE.md 의 유파 규약이고
결과만 받은 화면이 표시하려면 결과 안에 있어야 한다.

`yongshin` 과 `huisin` 이 null 을 받는 것은 중화 때문이다.
11.5 가 중화에 1순위와 2순위를 모두 두지 않았으므로 억부용신이 없는 상태를 타입이 표현해야 한다.
중화에서는 둘 다 null 이고 `needsJohuReview` 가 참이다.

`supportRatio` 와 `elementDistribution` 은 여덟 글자를 각 12.5퍼센트로 세는 단순 계수다.
지지는 본기 오행으로 센다. 지장간 가중 합산이 아니며 그 모델은 11.8 이 기각했다.

화면 권장: 유파가 갈리는 지점이므로 "용신 금(설기) / 차선 목(극제)"처럼 병기하고 적용 방식을 명시한다.

### 11.7 검증 기준 케이스

1995-01-27 14:39 여, 서울. 갑술(甲戌)·정축(丁丑)·무오(戊午)·기미(己未), 일간 무토.

- 네 요소 전부 참(축토 득령, 오화 인성 득지, 미토 득시, 지원 6/7 득세)이므로 태강이다.
- `supportRatio` 는 7/8 인 87.5퍼센트다(토 62.5 + 화 25). 포스텔러 표면 점수와 일치한다.
- 용신은 금(식상 설기), 희신은 수(재성)다. 포스텔러 실측(2026-07-25)의 억부용신 금과 일치한다.
- fixture: `verified-19950127-1439-F-seoul`

### 11.8 기각 기록: 8단계 방조비율 모델

선행 프로젝트에는 지장간 가중치로 세력을 계산해 방조 비율 백분율을 내고
극약, 태약, 신약, 중화신약, 중화신강, 신강, 태강, 극왕 8구간으로 나누는 모델이 있었다.
억부 분기도 관성 세력 10퍼센트 조건 등으로 더 세밀했다.

채택하지 않은 이유는 검증 케이스 13개가 5단계 모델 기준으로 작성되어 있어
8단계를 택하면 케이스를 전부 다시 만들어야 하기 때문이다.
자세한 경위는 [ADR 0007](adr/0007-strength-five-grade-model.md) 에 있다.

재도입 조건: 5단계의 해상도 부족이 실제 문제로 확인되고,
8단계 기준으로 verified 케이스를 다시 확보한 경우에 한한다.

## 12. 신살(神殺)과 길성

신살은 사주 영역 중 유파 편차가 가장 크고 전 유파가 합의한 표준 목록이 존재하지 않는다.
따라서 무엇을 채택하는지를 먼저 정하고, 채택한 것만 판정표를 여기에 고정한다.

구현은 `apps/web/src/lib/saju/sinsal.ts`, 판정표는 `tables.ts` 의 신살 섹션이다.

### 12.1 채택 등급

| 등급 | 정의                                                                   | 취급                                  |
| ---- | ---------------------------------------------------------------------- | ------------------------------------- |
| A    | 고전 문헌에 판정표가 실려 있고 문헌 간 표가 일치                       | 채택                                  |
| B    | 근거는 있으나 판정 기준(기준 간지, 포함 범위)이 유파별로 갈림          | 채택하되 따르는 유파를 이 문서에 명시 |
| C    | 고전 근거가 희박하고 자료마다 판정표가 다름 (한국 현대 실무 유래 계통) | 미채택                                |

C 를 미채택하는 이유는, 개수가 적어 보이는 것보다 근거를 댈 수 없는 판정이 섞이는 쪽이
결과 전체의 신뢰도를 더 떨어뜨리기 때문이다.
타 서비스에 있다는 사실은 채택 근거가 되지 않는다.

C 를 나중에 채택하려면 아래 세 조건을 모두 만족해야 한다.

1. 판정표의 출처를 문헌 단위로 특정한다.
2. 유파차가 있으면 어느 쪽을 따르는지와 그 이유를 이 문서에 기록한다.
3. 화면에서 A·B 등급과 구분해 표시한다.

### 12.2 채택된 신살: 일간 기준

| 신살       | 판정                                                                      | 분류 | 등급 |
| ---------- | ------------------------------------------------------------------------- | ---- | ---- |
| 천을귀인   | 갑무경→축미 / 을기→자신 / 병정→해유 / 신→인오 / 임계→묘사                 | 길성 | A    |
| 문창귀인   | 갑사 을오 병신 정유 무신 기유 경해 신자 임인 계묘                         | 길성 | A    |
| 정록(건록) | 갑인 을묘 병사 정오 무사 기오 경신 신유 임해 계자                         | 길성 | A    |
| 학당귀인   | 일간의 장생지. 갑해 을오 병인 정유 무인 기유 경사 신자 임신 계묘          | 길성 | A    |
| 관귀학관   | 일간 정관 오행의 장생지. 갑을→사 병정→신 무기→해 경신임계→인              | 길성 | A    |
| 태극귀인   | 갑을→자오 / 병정→묘유 / 무기→진술축미 / 경신→인해 / 임계→사신             | 길성 | B    |
| 금여성     | 건록의 2번째 다음 지지. 갑진 을사 병미 정신 무미 기신 경술 신해 임축 계인 | 길성 | A    |
| 양인       | 양간의 제왕지. 갑묘 병오 무오 경유 임자                                   | 흉살 | B    |

양인의 유파 선택: 양간 5개만 채택한다.
음간 양인(을진, 정미, 기미, 신술, 계축)은 문헌마다 위치가 갈리고 아예 인정하지 않는 유파도 있어 제외한다.

태극귀인의 유파 선택: 일간 기준을 채택한다.
년간 기준으로 보는 유파가 있으나, 이 앱의 다른 귀인류(천을, 문창, 학당, 관귀학관)가 모두 일간 기준이라
기준을 일치시킨다.

금여성은 일간 건록지에서 2칸 뒤 지지라 `JEONGNOK` 테이블에서 기계적으로 유도된다.
별도 테이블로 둔 것은 가독성 때문이며 두 표는 항상 이 관계를 만족해야 한다.

### 12.3 채택된 신살: 년지 기준

년지가 속한 방위 삼회 그룹으로 판정한다. 등급은 A 이고 분류는 둘 다 흉살이다.

| 년지 그룹 | 고신살 | 과숙살 |
| --------- | ------ | ------ |
| 해자축    | 인     | 술     |
| 인묘진    | 사     | 축     |
| 사오미    | 신     | 진     |
| 신유술    | 해     | 미     |

### 12.4 채택된 신살: 주(柱) 간지 기준

한 기둥의 천간과 지지 조합이 목록과 일치하면 그 기둥의 천간과 지지 양쪽에 붙는다.
지지 단독 판정과 달리 `hits` 가 stem 과 branch 두 개로 나온다.

| 신살     | 판정 간지                          | 분류 | 등급 |
| -------- | ---------------------------------- | ---- | ---- |
| 백호대살 | 갑진 을미 병술 정축 무진 임술 계축 | 흉살 | B    |
| 괴강살   | 경진 경술 임진 무술                | 중립 | B    |

적용 범위는 년월일시 네 기둥 전부다. 일주만 보는 유파가 있으나 그 경우 월주 백호가 누락된다.

백호대살의 등급 근거: 판정 간지 7개는 자료 간 이견이 없으나
고전 자평서 수록 여부를 확정하지 못해 A 가 아닌 B 로 둔다. 이 사실을 알고 채택한 것이다.

괴강살의 유파 선택: 협의 4간지만 채택한다. 임술과 무진을 더해 6간지로 보는 유파는 제외한다.

### 12.5 채택된 신살: 삼합 기준

기준 지지가 속한 삼합 그룹에 따라 판정 지지가 정해진다.

| 삼합 그룹 | 도화 | 역마 | 화개 | 겁살 | 망신 |
| --------- | ---- | ---- | ---- | ---- | ---- |
| 신자진    | 유   | 인   | 진   | 사   | 해   |
| 인오술    | 묘   | 신   | 술   | 해   | 사   |
| 사유축    | 오   | 해   | 축   | 인   | 신   |
| 해묘미    | 자   | 사   | 미   | 신   | 인   |

분류는 도화, 겁살, 망신이 흉살이고 역마와 화개가 중립이다.

기준 지지의 범위: 년지를 기본으로 하고, 일지가 년지와 다른 삼합 그룹일 때만 일지 기준을 병행한다.
같은 그룹이면 판정 결과가 동일하므로 중복 판정하지 않는다.
두 기준은 `basis` 필드(`삼합(년지)` 와 `삼합(일지)`)로 구분한다.

년지는 고전의 원칙 기준이고 일지 병행은 현대 실무에서 널리 쓰인다.
월지나 시지를 기준으로 삼는 방식은 문헌 근거를 확인하지 못해 채택하지 않는다. 경위는 12.8 에 있다.

### 12.6 판정 결과의 구조

판정 결과는 `{ name, category, basis, hits }` 형태다.
`hits` 는 신살이 붙은 지점을 `{ pillar, position, char }` 로 가리킨다.

같은 신살이 서로 다른 `basis` 로 중복 판정될 수 있다.
계산 코어는 중복을 그대로 두고 표시 단계에서 이름 단위로 접는다.

### 12.7 기각 기록: 현침살 제거

현침살(천간 갑과 신, 지지 묘·오·미·신)은 글자의 획 모양에서 유래한 계통이라
고전 판정 근거가 약해 12.1 기준으로는 C 에 해당한다.
채택 기준을 만들기 전에 구현된 항목이었으나 기준을 소급 적용해 제거했다.

신규 신살을 추가할 때 현침살을 선례로 삼지 않는다.
재도입하려면 12.1 의 C 승격 3조건을 만족해야 한다.

### 12.8 기각 기록: 삼합 신살의 기준 지지 전 범위 확장

타 서비스(포스텔러) 결과에서는 삼합 신살이 네 지지 전부를 각각 기준으로 삼은 것처럼 나타난다.
이 앱에는 도입하지 않는다.

근거가 명식 1개를 역산한 추정뿐이고, 그 명식에는 인신사해가 하나도 없어
역마, 겁살, 망신으로 반증할 기회조차 없었다.
타 서비스의 출력은 12.1 이 말하는 채택 근거가 아니다.
천문성과 귀문관살을 미채택한 것과 같은 기준을 여기에도 적용한다.

재검토 조건은 월지나 시지 기준을 지지하는 문헌 근거를 확보한 경우에 한한다.
타 서비스와의 출력 차이는 재검토 사유가 아니다.

### 12.9 미채택 목록

C 등급이라 채택하지 않은 것: 천문성, 귀문관살, 황은대사, 급각살, 단교관살.

A·B 등급이지만 아직 미구현이라 추가 후보인 것: 천덕귀인, 월덕귀인(월지 기준, 삼명통회 계열).
