# 00. 문서 작성 가이드

> 이 문서는 saju-ai 프로젝트 문서를 어떻게 쓰고 관리할지를 정의한다. 새 문서를 추가하거나 기존 문서를 고칠 때 이 규칙을 따른다.

## 1. 문서는 어디에 두는가

- 모든 프로젝트 문서는 저장소 루트의 `docs/`에 둔다.
- 특정 모듈에만 해당하는 짧은 설명은 해당 폴더의 `README.md`로 둔다.
  - 예) `apps/web/src/lib/saju/README.md`
- "왜 이렇게 결정했는가"를 남기는 의사결정 기록은 `docs/adr/`(Architecture Decision Record)에 번호순으로 둔다.

```
docs/
├── 00-documentation-guide.md
├── 01-overview.md
├── 02-architecture.md
├── 03-frontend-rules.md         화면 규칙 SSOT
├── 05-saju-domain-rules.md      사주 도메인 SSOT
├── 06-code-working-rules.md     코드 작업 방식
├── 07-sinsal-rules.md           신살 SSOT
├── mockups/                     화면 목업 HTML
└── adr/                         결정 기록. 번호순
```

### 1.1 무엇을 기준으로 쪼개는가

길이가 아니라 참조 관계로 쪼갠다. 서로를 자주 참조하는 규칙은 한 문서에 둔다.
길이 규칙(5장)보다 이쪽이 우선한다.

`05-saju-domain-rules.md` 가 그 예다. 스크롤 5번을 넘지만 쪼개지 않는다.
입력 시각에서 팔자와 운으로 가는 한 줄기라 장 사이 대조가 잦고,
검증기가 대운 하나를 확인할 때도 머리말부터 10장까지 열어 본다.
파일이 갈리면 그 대조가 grep 으로 밀린다.

신살을 `07-sinsal-rules.md` 로 뗀 것은 반대 경우다.
완성된 팔자를 받는 판정이라 05 의 어느 장도 참조하지 않는다.

부피가 문제면 쪼개기 전에 있을 자리가 아닌 것을 먼저 뺀다.
기각 기록과 결정의 경위는 ADR 이 맡는다.

## 2. 파일 네이밍 규칙

- 소문자 + 하이픈(`kebab-case`)을 사용한다. `saju-domain-rules.md` 는 맞고 `SajuDomainRules.md` 는 틀리다.
- 읽는 순서가 중요한 문서는 앞에 2자리 번호를 붙인다. (`01-overview.md`)
- ADR 은 4자리 번호 + 요약을 붙인다. (`0007-strength-five-grade-model.md`)
- 루트 안내 문서만 대문자 `README.md`로 둔다.

## 3. 문서 한 편의 표준 구조

```markdown
# NN. 문서 제목

> 한두 문장으로 이 문서가 무엇을 다루는지 요약.

## 1. 큰 주제
### 1.1 세부 주제
- 핵심을 불릿으로
- 코드/표/다이어그램으로 보강
```

- 제목(`#`)은 문서당 하나.
- 섹션은 `##`, 하위는 `###`까지만. 4단계 이상 들어가면 문서를 쪼갠다.

## 4. ADR 작성 규칙

ADR 은 아래 형식을 지킨다. 이 프로젝트의 모든 ADR 이 같은 골격을 갖는다.

```markdown
# ADR NNNN. 결정을 한 문장으로

- 상태: 채택(Accepted) | 대체됨(Superseded by ADR NNNN) | 폐기(Deprecated)
- 날짜: YYYY-MM-DD

## 배경
## 결정
## 이유
## 트레이드오프 / 대안
## 영향
```

- 결정을 바꿀 때는 기존 ADR 을 수정하지 않고 새 ADR 을 쓴 뒤 기존 것의 상태를 `대체됨`으로 바꾼다.
- 채택하지 않기로 한 것도 기록한다. 같은 논의가 반복되는 것을 막는 것이 ADR 의 주된 값어치다.
- 큰 구조·기술 결정은 코드보다 ADR 을 먼저 쓴다.

## 5. 마크다운 스타일 규칙

문서(`*.md`)와 Claude 의 마크다운 답변 모두에 적용한다.
규칙 목록은 `.claude/rules/markdown-style.md` 에 있고 그 파일이 전부다.
검사하는 도구는 없다.

## 6. 문서를 최신으로 유지하는 규칙

1. 코드와 문서는 같은 PR 에서 바꾼다.
2. 도메인 SSOT 는 [`05-saju-domain-rules.md`](05-saju-domain-rules.md) 와
   [`07-sinsal-rules.md`](07-sinsal-rules.md) 다. 어긋났을 때 어느 쪽을 고치는지는 두 문서 머리말에 있다.
3. 문서 리뷰도 코드 리뷰처럼 PR 로 진행한다.

## 7. 문서 추가 체크리스트

- [ ] 파일명이 `kebab-case` + (필요 시) 번호 규칙을 따르는가
- [ ] 최상단에 한 줄 요약이 있는가
- [ ] 루트 [`CLAUDE.md`](../CLAUDE.md) 의 문서 표에 링크를 추가했는가

문장과 기호는 5장이 가리키는 규칙 파일의 확인 목록을 쓴다. 여기 옮겨 적지 않는다.
