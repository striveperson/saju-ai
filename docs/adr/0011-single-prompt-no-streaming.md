# ADR 0011. 해석은 단일 프롬프트로 한 번에 생성하고 완성 후 보여준다

- 상태: 채택(Accepted)
- 날짜: 2026-08-05

## 배경

[ADR 0005](0005-rule-engine-plus-llm-interpretation.md) 에서 판정 결과를 LLM 에 넘겨 해석문을 받기로 했다.
해석을 총평, 성격, 직업, 재물, 관계, 대운처럼 섹션으로 나눠 각각 생성할 수도 있고
한 번에 통째로 받을 수도 있다. 응답을 스트리밍할지도 정해야 한다.

## 결정

1. 판정 결과 전체를 한 번의 프롬프트에 담아 해석문을 통째로 받는다.
2. 스트리밍하지 않는다. 응답이 완성되면 보여준다.
3. 공급자는 Gemini Flash Lite 계열을 쓴다.
4. 공급자를 설정으로 교체할 수 있게 하고, 개발 기본값은 `stub` 으로 둔다.
   `stub` 은 외부를 호출하지 않으므로 API 키 없이 개발과 테스트가 된다.
5. 캐시 키는 `sha256(팔자 + 판정 결과 + 계산 옵션 + 프롬프트 버전 + 모델 버전)` 이다.

## 이유

- 섹션을 나누면 섹션 간 내용이 어긋난다. 성격에서 한 말과 직업에서 한 말이 다른 전제 위에 서게 된다.
  한 번에 보면 모델이 전체 맥락을 쥐고 쓴다.
- 프롬프트와 문체 관리 대상이 하나로 유지된다. 섹션마다 프롬프트를 두면 그만큼 관리 비용이 늘어난다.
- SSE 인프라가 없어도 되고 공유 페이지 SSR 과 렌더링 경로가 같아진다
  ([ADR 0009](0009-share-link-policy.md)).
- 캐시 키에 프롬프트 버전과 모델 버전을 넣으면 프롬프트를 고칠 때 캐시가 자연히 무효화된다.
  별도 무효화 절차가 필요 없다.

## 트레이드오프 / 대안

- 대안 1: 섹션별 분할 생성에 순차 스트리밍. 캐시 적중률이 높고 사용자가 기다리는 체감이 짧지만
  호출 수가 늘고 섹션 간 중복과 모순을 관리해야 한다.
- 대안 2: 단일 프롬프트에 SSE 스트리밍. 첫 글자가 빨리 나오지만 스트리밍 인프라가 필요하고
  Vercel 서버리스에서 장시간 연결을 유지해야 한다.
- 캐시가 빗나가면 첫 생성까지 수 초간 해석 영역이 비어 있다. 사용자가 이탈할 수 있는 구간이다.
- 해석 일부만 마음에 안 들어도 전체를 다시 생성해야 한다.
- 완화 방법은 이렇다. 계산 결과(팔자, 오행, 신강약, 용신, 신살)는 로컬에서 즉시 나오므로 먼저 그린다.
  해석 영역만 로딩 상태로 두면 빈 화면을 보는 시간이 없다.

## 재검토 조건

응답 지연이 실제로 이탈로 이어지는 것이 확인되면 섹션 분할과 스트리밍을 다시 검토한다.
그때는 이 ADR 을 대체하는 새 ADR 을 쓴다.

## 영향

- Gemini 응답 시간이 Vercel 서버리스 실행시간 제한 안에 들어오는지 확인해야 한다
  ([ADR 0012](0012-vercel-deploy.md)).
- 계산 옵션(진태양시, 야자시 정책)이 캐시 키에 포함된다.
  옵션이 다르면 판정이 다르고 해석도 다르다([ADR 0006](0006-manseryeok-and-time-correction.md)).
- 프롬프트 버전을 명시적으로 관리한다. 프롬프트 파일을 고치면 버전을 올린다.
