# ADR 0013. 계산 엔진의 순수성은 lint 규칙과 훅으로 강제한다

- 상태: 채택(Accepted)
- 날짜: 2026-08-05

## 배경

[ADR 0001](0001-monorepo-pnpm-workspaces.md) 에서 계산 엔진을 별도 패키지로 빼지 않고
`apps/web/src/lib/saju/` 폴더에 두기로 했다.
패키지였다면 `package.json` 의 빈 dependencies 가 외부 의존을 막았겠지만, 폴더에는 그런 경계가 없다.

계산 엔진이 순수해야 하는 이유는 두 가지다.
검증 케이스가 언제 어디서 실행하든 같은 결과를 내야 하고,
[ADR 0003](0003-spa-bundle-for-app.md) 의 오프라인 동작을 위해 엔진이 네트워크나 런타임 환경에 기대면 안 된다.

## 결정

두 겹으로 막는다.

1. lint 규칙으로 `src/lib/saju/` 에서 외부 모듈 import 를 금지한다.
   React, 날짜 라이브러리, Supabase 클라이언트, UI 코드가 전부 대상이다.
   허용 예외는 KASI 절기·음력 데이터 모듈뿐이고, 그 목록을 규칙에 명시적으로 적는다.
2. PostToolUse 훅으로 해당 경로 파일을 저장할 때 아래를 차단한다.
   `Date.now()`, 인자 없는 `new Date()`, `Math.random()`, 실행 환경 타임존에 의존하는 호출.

엔진이 현재 시각이나 실행 환경 타임존을 읽으면 테스트가 재현되지 않는다.
시각은 항상 인자로 받는다.

## 이유

- form-flow 가 `check-manual-memo.sh` 와 `check-suspense-query.sh` 로 같은 방식의 제약을 이미 쓰고 있다.
  검증된 패턴이라 새로 설계할 것이 없다.
- 훅은 저장 시점에 차단 피드백을 준다. 리뷰까지 가지 않고 그 자리에서 고쳐진다.
- lint 규칙과 훅은 잡는 것이 다르다.
  lint 는 import 경계를, 훅은 함수 호출을 본다. 한쪽만으로는 구멍이 남는다.

## 트레이드오프 / 대안

- 대안 1: `packages/saju-core` 로 승격해 `package.json` 으로 강제한다.
  가장 확실하지만 소비자가 하나뿐인 지금은 설정 비용이 이득보다 크다
  ([ADR 0001](0001-monorepo-pnpm-workspaces.md)).
- 대안 2: 폴더 컨벤션과 코드 리뷰에만 의존한다. 비용이 0 이지만 사람이 놓치면 그대로 통과한다.
  이 프로젝트에서 엔진의 순수성은 결과의 신뢰도와 직결되므로 사람에게 맡기지 않는다.
- 훅이 정당한 예외를 막을 수 있다. 예외가 필요하면 주석으로 사유를 남겨 통과시키는 경로를 둔다.
- 규칙이 늘어나면 개발 흐름이 끊긴다. 규칙은 이 두 가지로 제한하고 늘리지 않는다.

## 승격 조건

앱에 네이티브 화면이 생겨 엔진을 웹과 앱이 공유해야 하면 `packages/saju-core` 로 옮긴다.
그때는 빈 dependencies 가 lint 규칙을 대신하므로 이 ADR 을 대체하는 새 ADR 을 쓴다.

## 영향

- `.claude/hooks/` 에 엔진 순수성 훅을 새로 작성한다. 설정은 `.claude/settings.json` 에 둔다.
- lint 설정에 경로 기반 import 제한 규칙을 추가한다.
- KASI 데이터 모듈은 예외 목록에 들어가므로 그 모듈 자체도 순수해야 한다.
  데이터를 파일에서 읽는 형태여야 하고 네트워크를 타면 안 된다.
