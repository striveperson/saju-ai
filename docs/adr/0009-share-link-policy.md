# ADR 0009. 공유 페이지는 전부 공개하고, 대신 링크 통제권을 사용자에게 준다

- 상태: 채택(Accepted)
- 날짜: 2026-08-05

## 배경

[ADR 0008](0008-social-login-server-storage.md) 에서 사주를 URL 로 공유하기로 했다.
공유 링크는 인증 없이 열리므로 무엇을 보여줄지 정해야 한다.

처음에는 이름과 생년월일시를 가리고 팔자와 해석만 보여주는 안을 검토했다.
그런데 사주팔자 여덟 글자가 보이면 만세력 역산으로 출생 시각을 되찾을 수 있다.
년월일주 조합이 60년 주기 안에서 날짜를 특정하고 시주가 2시간 구간까지 좁힌다.
생년월일시를 가려도 가린 효과가 거의 없다는 뜻이다.

## 결정

1. 공유 링크를 열면 이름, 생년월일시, 사주팔자, 오행, 신강약, 용신, 신살, 해석문을 모두 보여준다.
   마스킹 분기를 두지 않는다.
2. URL 은 자체 도메인의 짧은 경로에 충분히 긴 랜덤 ID 를 붙인다(`/s/{nanoid}`).
   외부 단축 서비스를 쓰지 않는다.
3. 공유 링크는 기본으로 존재하지 않는다. 사용자가 명시적으로 생성해야 만들어진다.
4. 사용자는 언제든 링크를 비활성화할 수 있고, 비활성화하면 즉시 404 가 된다.
5. 공유 페이지에 `noindex` 를 걸어 검색엔진에 색인되지 않게 한다.
6. 링크 생성 화면에 무엇이 공개되는지 명시한다.

## 이유

- 가릴 수 없는 것을 가린 척하지 않는다.
  이름만 가리는 것은 실질 방어가 되지 않으면서 공유의 재미와 구현·QA 단순성만 잃는다.
- 방어에 쓸 비용을 링크 통제 쪽으로 옮긴다.
  내용을 못 가리면 누가 볼 수 있는지를 통제하는 것이 유일하게 실효가 있는 수단이다.
- 외부 단축 서비스를 쓰지 않는 이유는 두 가지다.
  짧은 ID 는 엔트로피가 낮아 무작위 대입으로 남의 링크가 열릴 수 있고,
  제3자 서비스에 링크 기록이 남는다.

## 트레이드오프 / 대안

- 대안 1: 해석문과 오행 비율만 공개하고 팔자까지 숨긴다. 역산을 실질적으로 차단하는 유일한 안이지만
  공유받은 사람이 명식을 못 보게 되어 사주 서비스로서 반쪽짜리 페이지가 된다.
- 대안 2: 링크에 유효기간을 두고 재발급하게 한다. 유출된 링크의 수명을 제한하지만
  공유받은 사람 입장에서 어느 날 깨진 링크가 된다. 필요해지면 나중에 추가한다.
- 링크가 단톡방 밖으로 새면 가린 것이 없다. 되돌리는 수단은 비활성화뿐이다.
- 사용자가 위험을 인지하지 못한 채 공유할 수 있다. 링크 생성 화면의 고지가 그 위험을 상쇄해야 한다.

## 영향

- 개인정보 처리방침에 공개 범위와 사용자의 통제 수단(생성, 비활성화)을 명시해야 한다.
- `share_links` 테이블은 활성 여부 플래그를 갖는다. 비활성 링크는 조회 시 404 로 응답한다.
- 공유 페이지는 인증 없이 서버 키로 조회하는 경로다.
  이 경로가 사주 프로필 전체를 읽을 수 있으므로 권한 정책에서 별도로 다룬다
  ([ADR 0010](0010-supabase-auth-and-db.md)).
