# ADR 0006. 만세력과 시간 보정 규칙은 기존 프로젝트의 SSOT 를 승계한다

- 상태: 채택(Accepted)
- 날짜: 2026-08-05

## 배경

사주 앱에서 기술적 위험이 가장 큰 부분은 만세력 계산이다.
절기 경계, 야자시 처리, 한국 표준시 이력, 서머타임, 진태양시 보정 중 하나만 틀려도
결과 전체가 무의미해진다.

`/Users/mychoi/f-lab/saju` 에 같은 사용자가 만든 사주 앱이 있고,
`.claude/docs/saju-domain-rules.md` 에 이 규칙들이 이미 정리되어 있다.
공인 만세력 대조를 거친 검증 케이스 13개도 함께 있다.

## 결정

규칙을 새로 정의하지 않고 승계한다. 승계 내용은 아래와 같다.

1. 시간 보정 파이프라인 순서는 표준시 이력 정규화, 서머타임 해제, 진태양시 보정(옵션), 시지 판정이다.
2. 진태양시 보정은 사용자 옵션이며 기본값은 끔이다. 경도 입력이 원칙이다.
   경도를 모를 때만 서울 관례값 -30분을 폴백으로 쓰되, 표준 자오선이 127.5도이던 시기에는 0분으로 조정하고
   폴백을 썼다는 사실을 화면에 명시한다. -30분 고정만 제공하고 경도 입력이 불가능한 구현은 오류로 본다.
3. 야자시와 조자시도 옵션(`ziPolicy`)이다. 정자시설은 `nextDay`, 야자시설은 `sameDay` 다.
   어느 값을 택하든 결과 화면에 적용된 방식을 명시한다.
4. 한국 표준시 이력(1908~1911 및 1954~1961 은 UTC+8:30)과 서머타임(1948~1951, 1955~1960, 1987~1988)은
   tz database `Asia/Seoul` 기준으로 처리한다.
5. 절기 시각은 KASI 데이터를 쓴다. 근사 공식으로 계산하지 않는다.
6. 음력은 입력 편의 기능일 뿐이다. KASI 공식 데이터로 변환하고 윤달 플래그를 입력받는다.
   자체 음력 산출 알고리즘을 구현하지 않는다.
7. 일주 앵커 값은 문서에 하드코딩하지 않는다. `verified: true` 검증 케이스 3개 이상으로 확정한다.

승계한 내용은 [`docs/05-saju-domain-rules.md`](../05-saju-domain-rules.md) 에 담기며,
그 문서가 이 프로젝트의 도메인 SSOT 가 된다.

## 이유

- 이 규칙들은 취향이 아니라 사실 확인의 문제다. 한 번 제대로 조사한 결과를 다시 조사할 이유가 없다.
- 검증 케이스 13개가 함께 오므로 계산 엔진을 구현하기 전에 회귀 테스트가 이미 존재하는 상태가 된다.
- 진태양시와 야자시를 옵션으로 둔 판단도 그대로 가져간다.
  두 사안 모두 유파가 갈리는 지점이라 단일 정답을 강요하면 특정 유파 사용자를 잃는다.

## 트레이드오프 / 대안

- 대안: 진태양시를 기본 적용하는 정통 명리 방식으로 간다. 이론적으로는 더 정확하지만
  상용 만세력 다수가 미적용이라 사용자가 다른 곳과 비교했을 때 결과가 어긋난다.
  기본값을 끔으로 두고 옵션으로 제공하면 양쪽을 모두 보여줄 수 있다.
- 옵션이 두 개(진태양시, 야자시) 늘면 조합이 네 가지가 된다.
  캐시 키와 검증 케이스가 그만큼 늘어나고 화면에도 적용된 방식을 항상 표기해야 한다.
- KASI 데이터에 의존하므로 지원 연도 범위가 데이터 범위에 묶인다.

## 영향

- 계산 옵션(`trueSolarTime`, `ziPolicy`, 경도)이 사주 프로필의 일부로 저장된다.
  옵션이 다르면 다른 사주이므로 해석 캐시 키에도 포함된다.
- 승계 과정에서 원본 문서의 신강약 절은 그대로 옮기지 않는다.
  두 모델이 충돌하고 있어 [ADR 0007](0007-strength-five-grade-model.md) 에서 하나로 정리한다.
