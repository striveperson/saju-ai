# ADR 0019. 출생지는 필수 입력이고 경도는 주소 API 로 찾는다

- 상태: 채택(Accepted)
- 날짜: 2026-08-16

## 배경

[ADR 0016](0016-true-solar-time-always-applied.md) 이 진태양시 보정을 항상 적용하기로 하면서
경도가 계산에 반드시 들어가는 값이 되었다.
[docs/05](../05-saju-domain-rules.md) 7.3 은 그 결과를 이렇게 적는다.
"경도 입력이 원칙이다. (…) -30분 고정만 제공하고 경도 입력이 불가능한 구현은 오류로 본다."

입력 목업 `docs/mockups/input-screen.html` 은 시도 17개와 대표 경도를 내장 목록으로 들고 있었다.
그 자리 주석이 "목업 전용 임시값이다. 출처를 확인하기 전에는 계산 엔진으로 옮기지 않는다" 이고,
"실제 앱에서는 searchSido 를 주소 API 호출로 바꾼다" 로 방향까지 적어 두었다.

선택 단위는 도와 시로 정했다. 시도 17개는 너무 거칠다.
경상북도는 동서로 1.5도 가까이 걸쳐 대표값 하나로는 6분이 어긋난다.
반대로 읍면동까지 내려가면 항목이 수천 개가 되고 사용자가 자기 출생지를 그 정밀도로 기억하지 못한다.

## 결정

1. 지역 검색을 카카오 로컬 주소 검색 API 에 맡기고 `src/routes/api/regions.ts` 가 중계한다.
   REST 키는 그 라우트 안에서만 읽는다. 클라이언트 번들에 넣지 않는다.
2. 결과는 도와 시까지다. 경기도, 의왕시, 전주시, 세종특별자치시가 나오고
   완산구, 분당구, 강남구와 읍면동은 걸러낸다.
   군은 남긴다. 시의 아래가 아니라 옆이고, 빼면 양평군 출생이 경기도밖에 고를 것이 없다.
3. 출생지는 필수 입력이다. 고르지 않으면 제출할 수 없다.
   이 항이 [ADR 0003](0003-spa-bundle-for-app.md) 3항의 입력 부분을 대체한다.
   앱은 이제 네트워크 없이 사주를 낼 수 없다.
4. 응답에서 쓰는 것은 경도(`x`)뿐이다. 위도는 받아도 버린다.
   균시차를 넣지 않기로 한 이상([docs/05](../05-saju-domain-rules.md) 7.3) 위도가 들어갈 계산이 없다.
   시간 보정은 `(경도 - 135) × 4분` 이다.
5. 시도 17개 내장 목록을 코드로 옮기지 않는다. 목업에서도 지운다.
6. 엔진의 -30분 폴백과 `true-solar-fallback` 표시는 그대로 둔다.
   입력 지면이 그 경로로 보내지 않을 뿐이고, `docs/05` 7.3 이 요구하는 표시 의무는 남는다.
   저장된 사주나 공유 링크가 경도 없이 들어오는 경우가 아직 열려 있다.

## 이유

값의 출처를 우리가 지지 않는다. 도와 시 단위면 항목이 200개에 가깝고,
행정구역은 통합과 승격으로 실제로 움직인다.
2023년에 강원도가 강원특별자치도가 되고 전라북도가 전북특별자치도가 된 것이 목업 목록에 이미 반영되어 있다.
번들하면 그 갱신이 우리 일이 되고, 갱신을 놓쳐도 아무것도 실패하지 않는다.
틀린 이름과 틀린 경도가 조용히 나간다. 이 저장소가 만세력 데이터에 대해 피하려는 실패와 같은 부류다.

출생지를 필수로 두는 것은 서울 관례값이 답으로 나가는 것을 막기 위해서다.
-30분 폴백은 서울에서 태어난 사람에게만 맞다. 부산은 -24분이라 6분이 어긋나고,
그 6분이 시지 경계에 걸리면 시주가 통째로 바뀐다.
결과 화면에 폴백을 썼다고 적어도 사용자가 그것을 읽고 고칠 방법은 결국 출생지를 넣는 것이다.
넣을 수 있는 자리를 만들어 두고 비운 채로 넘기게 하면, 대부분은 비우고 넘긴 뒤
서울 기준 사주를 자기 사주로 읽는다. `docs/05` 7.3 이 "경도 입력이 원칙이다" 로 적은 것이 이 뜻이다.

카카오를 고른 것은 REST 키가 도메인에 묶이지 않아서다.
서버에서 부르고 앱이 `capacitor://localhost` 오리진으로 그 서버를 다시 부르는 경로에 맞는다.

## 트레이드오프 / 대안

- 첫 API 라우트이고 첫 시크릿이다. `KAKAO_REST_API_KEY` 를 환경변수로 넣어야 하고,
  앱에서 부르려면 절대 URL 이 필요해 배포가 선행되어야 한다([ADR 0004](0004-api-routes-over-server-functions.md)).
  지금까지 서버 없이 굴러가던 저장소가 그렇지 않게 된다.
- 이것이 가장 큰 대가다. 오프라인이면 사주를 아예 못 낸다.
  [ADR 0003](0003-spa-bundle-for-app.md) 이 "앱은 네트워크 없이도 생년월일시 입력,
  사주팔자 계산, 판정 결과 화면까지 동작한다" 로 약속했고
  그 오프라인 동작을 App Store 심사 지침 4.2 에 대한 방어 논리로 쓴다.
  지하철에서 앱을 연 사람이 첫 화면에서 막히고, 심사 대응 논리도 다시 세워야 한다.
  대안이 둘 있고 둘 다 이 ADR 밖이다. 고른 출생지를 기기에 남겨 다음번에 오프라인으로 쓰게 하는 것과,
  검색이 안 될 때만 좁은 목록을 번들에서 꺼내 주는 것이다.
- 검색어가 제3자 서버에 남는다. 시군구 이름이라 그 자체로 사람을 특정하지 않지만,
  생년월일시와 달리 우리가 통제하지 못하는 곳에 기록이 생기는 것은 맞다.
  중계 라우트는 검색어를 우리 로그에도 남기지 않는다.
- 응답 모양에 매인다. 카카오가 형식을 바꾸면 조용히 구가 섞여 나오거나 시가 사라진다.
  픽스처 테스트가 형식을 붙잡아 두지만 실제 응답이 바뀐 것은 잡지 못한다.
  2026-08-16 에 잰 결과는 이렇다. 구가 있는 시도 `region_2depth_name` 이
  `전주시` 이지 `전주시 완산구` 가 아니고, 구와 읍면동은 검색 자체에서 걸러진다.
- 시도 이름이 약칭으로 온다. 서울특별시가 `서울`, 경기도가 `경기` 인데
  제주특별자치도와 세종특별자치시는 온전한 이름이라 표기가 섞인다.
  고쳐 적지 않는다. 맞추려면 우리가 표를 들어야 하고 그것이 이 ADR 이 피하려는 것이다.
- 대안: 도와 시 목록 200줄을 번들한다. 오프라인이 온전히 유지되고 키도 서버도 필요 없다.
  버린 이유는 위의 출처 문제이고, 다시 검토할 값어치는 있다.
  검색 함수를 교체 가능한 자리로 두어 그때 그 함수만 갈아 끼우게 한다.
- 대안: VWorld 지오코더. 국가가 내는 데이터라 출처가 더 단단하다.
  키가 도메인에 묶여 서버 중계와 앱 오리진 양쪽에 맞추기 어려워 뺐다.
- 대안: 사용자가 경도를 숫자로 직접 넣는다. 의존이 0 이다.
  자기 출생지의 경도를 아는 사람이 없다.

## 영향

- `src/routes/api/` 가 생긴다. [docs/02](../02-architecture.md) 4장과
  [docs/03](../03-frontend-rules.md) 3장의 트리에 그 자리가 들어간다.
- [docs/01](../01-overview.md) 3장 흐름도의 첫 단계가 네트워크를 탄다.
  "네트워크 없이도 D 단계까지 도달한다" 가 더 이상 참이 아니다.
- 목업의 `SIDO` 상수와 `searchSido` 가 API 호출로 바뀐다.
  제출 조건에 시각이 들어간다.
  시각은 [docs/05](../05-saju-domain-rules.md) 12.1 이 `ChartInput.birth` 에서 필수로 받기 때문이다.
- `true-solar-fallback` 경고가 입력 지면에서는 도달하지 않는 경로가 된다.
  엔진과 결과 지면의 처리는 남는다. 6항이 그 이유다.
- Vercel 배포가 앱 작업의 선행 조건이 된다. 루트 CLAUDE.md 의 MCP 표에서
  `vercel` 서버가 "배포할 때" 로 미뤄져 있는데 그 시점이 당겨진다.
- `true-solar-fallback` 경고가 실제로 나가는 경로가 생긴다.
  지금까지는 미리보기 상수가 늘 경도를 넣어 그 문구가 화면에 뜬 적이 없다.
- zod 가 `apps/web` 에 들어온다. [ADR 0018](0018-frontend-rules-selective-port.md) 영향 절이
  "설치 시점은 정하지 않았다. 검증이 필요한 첫 화면 작업에서 정한다" 로 남겨 둔 것이고,
  카카오 응답과 히스토리 state 가 그 첫 대상이다.
- `src/shared/` 와 `@shared/*` 별칭이 생긴다.
  입력 지면과 결과 지면이 함께 쓰는 값의 타입이 어느 한쪽 지면 안에 있을 수 없다.
- 균시차를 넣기로 하면 위도가 필요해진다. 그때 4항을 다시 본다.
