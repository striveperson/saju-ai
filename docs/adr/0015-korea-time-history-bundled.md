# ADR 0015. 한국 표준시 이력은 tz database 를 손으로 옮겨 번들한다

- 상태: 채택(Accepted)
- 날짜: 2026-08-09

## 배경

[ADR 0006](0006-manseryeok-and-time-correction.md) 4항은 한국 표준시 이력과 서머타임을
tz database `Asia/Seoul` 기준으로 처리한다고 정했다.
[ADR 0013](0013-saju-engine-purity-enforcement.md) 은 계산 엔진에서 날짜 라이브러리를 포함한
외부 import 를 금지하고, 실행 환경 타임존에 의존하는 호출도 훅으로 막는다.

두 결정이 충돌한다. 런타임에 tz 라이브러리를 붙이면 0013 위반이고,
아무것도 붙이지 않으면 0006 을 지킬 수 없다.
시간 보정 파이프라인 코드가 없어서 지금까지 드러나지 않았다.

[ADR 0014](0014-kasi-data-bundled-not-fetched.md) 가 절기에서 같은 모양의 문제를 이미 풀었다.
값의 출처와 런타임 의존을 분리하는 방식이다.

`Asia/Seoul` 의 실제 규모도 확인했다. 1900~2100 구간에 전환이 29번 있고
그중 오프셋이 바뀌는 것은 다섯이다. 나머지는 서머타임 시작과 종료다.

## 결정

tz database 를 값의 출처로 삼되 런타임 의존이 아니라 번들된 표로 옮긴다.

1. `apps/web/src/lib/saju/data/korea-time.ts` 에 전환 29건을 담는다.
   자동 생성하지 않고 손으로 옮기며, 각 행에 원본 전환 정보를 주석으로 남긴다.
2. 리뷰용 JSON 사본을 두지 않는다. ADR 0014 6항이 사본을 둔 이유는 바이너리의 diff 를
   읽을 수 없어서였는데, 29행짜리 리터럴은 PR 에서 그대로 읽힌다.
3. 정답지는 `apps/web/scripts/dump-tzdb-seoul.mjs` 가 뜬
   `apps/web/src/lib/saju/fixtures/tzdb-asia-seoul.json` 이다.
   `data/korea-time.test.ts` 가 표와 정답지를 대조한다.
4. 정답지의 값은 컴파일된 TZif 바이너리에서 읽는다. `Intl` 은 오프셋만 주고
   서머타임 여부와 약칭(KST, KDT, JST, LMT)을 주지 않기 때문이다.
   같은 값을 `Intl` 로 다시 뽑아 교차검증한다. tzdata 사본 둘이 독립적으로 일치해야 통과다.
5. tzdata 버전 문자열을 고정하지 않는다. 정답지에 기록만 하고 단언은 전환 목록 자체로 한다.
6. 정규화 기준은 UTC+9 로 고정하고 진태양시 기준 자오선은 항상 135도다.
   시대별 표준 자오선 표를 두지 않는다.
7. 1908년 4월 이전은 tz database 를 따라 UTC+8:27:52 로 해석하고 결과 화면에 표시한다.
8. 존재하지 않는 벽시계와 두 번 존재하는 벽시계는 조용히 고르지 않는다.
   기본 해석과 고르지 않은 쪽을 함께 반환하고, 화면 표기를 반환 타입으로 강제한다.
9. 출생 기록이 서머타임 시각인지를 입력으로 받는다. 기본값은 모른다는 뜻의 `unknown` 이다.

승계 규칙은 [docs/05-saju-domain-rules.md](../05-saju-domain-rules.md) 7장에 담긴다.
ADR 0006 은 채택 상태를 유지한다. 이 ADR 은 4항의 조달 방식을 구체화할 뿐이고
나머지 6개 결정은 그대로 유효하다. ADR 0014 가 5항에 대해 한 것과 같은 관계다.

## 이유

29행이면 사람이 읽는다. 절기는 4,824건이라 압축이 필요했지만 여기는 그렇지 않다.
손으로 옮기면 각 행 옆에 그 전환이 무엇인지 적을 수 있고, 잘못 옮긴 값은 정답지 대조가 잡는다.
자동 생성으로 얻을 것이 없는 규모다.

전환 목록이 완전하면 전 구간 일치가 따라온다. 생성기가 1900~2101 을 6시간 간격으로 훑는데
한국의 어떤 오프셋 구간도 6시간보다 짧았던 적이 없다. 표가 목록과 일치하면 그 사이 모든 순간에서 일치한다.
매일 표본을 실으면 7만 행짜리 정답지가 되는데 그만큼의 값이 없다.

버전 문자열을 고정하지 않는 이유는 오탐 때문이다. tzdata 는 칠레나 이란의 규칙이 바뀌어도 판올림한다.
한국과 무관한 갱신마다 테스트가 깨지면 사람이 테스트를 믿지 않게 된다.
실제로 이 저장소의 시스템 TZif 는 2026c 이고 Node 의 ICU tzdata 는 2025c 인데
한국 구간에서 둘이 완전히 일치한다. 감시해야 할 것은 버전이 아니라 전환 목록이다.

교차검증을 넣은 것은 TZif 파서를 우리가 썼기 때문이다. 파서에 버그가 있으면
정답지가 조용히 틀리고 표도 같이 틀린다. `Intl` 은 완전히 다른 경로로 같은 데이터를 읽으므로
파서 오류와 데이터 오류를 분리한다. 격자 대조 293,656회가 그 역할을 한다.

자오선을 135도로 고정하는 것은 이중 적용을 막기 위해서다.
UTC+8:30 시기의 30분은 정규화가 이미 옮겼는데 자오선 127.5도를 다시 쓰면 30분이 두 번 들어간다.
docs/05 7.1 이 두 방식을 동등하다고 적은 것은 둘 중 하나만 쓸 때의 이야기다.

이상 구간에 예외를 던지지 않는 것은 분포 때문이다. 28개 중 24개가 자시 구간 안에 있다.
1988년 이전 전환이 전부 자정에 걸려 있어서 그렇다. 거부하면 그 시각에 태어난 사람이 서비스를 쓰지 못한다.
지원 범위 밖은 답이 없는 경우지만 여기는 답이 둘인 경우라 성질이 다르다.

## 트레이드오프 / 대안

- 대안: `Temporal` API 를 쓴다. 모호한 시각의 해석 규칙(`disambiguation`)이 표준화 과정에서
  오래 논의된 결과라 그대로 따를 수 있다. 폴리필이 곧 외부 의존이라 ADR 0013 에 걸려 탈락했다.
  판정 규칙은 참고했고 API 는 쓰지 않는다.
- 대안: `Intl.DateTimeFormat` 으로 런타임에 오프셋을 구한다. 표를 유지할 필요가 없다.
  훅이 막는 호출이고, 실행 환경 ICU 의 tzdata 버전에 따라 결과가 달라져 재현성이 깨진다.
  검증 케이스가 개발 기기와 CI 에서 다른 값을 낼 수 있다.
- 대안: `luxon` 이나 `date-fns-tz` 를 번들한다. ADR 0013 의 날짜 라이브러리 금지에 정면으로 걸린다.
- 대안: 절기처럼 base64 바이너리로 굽는다. 29건에 압축이 필요 없고 리뷰 가능성만 잃는다.
- 대안: 이상 구간 입력을 거부한다. 조용히 틀릴 여지가 0 이 되지만 자시 출생자가 막힌다.
- 표를 손으로 유지한다. tzdata 가 한국 규칙을 바꾸면 사람이 옮겨 적어야 한다.
  1988년 이후 변경이 없었으므로 빈도는 낮지만, 대조 테스트가 실패로 알려주는 것에 의존한다.
- TZif 파서를 직접 썼다. RFC 8536 의 일부만 구현했고 윤초 블록과 POSIX 푸터를 건너뛴다.
  파일 형식이 바뀌면 생성기가 깨진다.
- 모호한 시각의 기본 해석에 만세력 근거가 없다. 앞의 것을 쓰기로 한 것은 `Temporal` 관행을 따른 것이고
  공인 만세력이 어떻게 하는지는 확인하지 못했다. 그래서 대안 시각을 함께 반환한다.
- 옵션이 둘(`dstAssumption`, `ambiguityChoice`) 늘어난다.
  ADR 0006 이 이미 네 가지 조합을 예고했는데 그보다 늘어난다.
  다만 둘 다 이상 구간에 걸린 입력에서만 결과를 바꾼다.

## 영향

- 계산 엔진에 `data/korea-time.ts` 와 `time.ts` 가 생긴다.
  `pillars.ts` 의 `CalendarDateTime` 과 `julianDayNumber` 는 `calendar.ts` 로 옮긴다.
  파이프라인이 기둥 모듈에 의존하지 않게 하기 위해서다.
- `pillars.test.ts` 의 UTC+9 하드코딩 스텁이 사라진다.
  기존 `verified` 케이스는 전부 UTC+9 구간이고 서머타임 밖이라 값이 달라지면 안 된다.
- 결과 화면이 표시해야 할 항목이 늘어난다. 표준시가 UTC+9 가 아니던 시기,
  서머타임 해제 여부와 그 근거, 이상 구간 해석, 진태양시 폴백 사용이다.
  화면이 아직 없으므로 반환 타입에 담아 두고 표기는 화면을 만들 때 한다.
- 절입 시각 근처 표시(ADR 0014 영향 절)와 이상 구간 표시가 화면에서 같은 자리를 쓴다.
  두 경고의 문구 체계는 아직 정하지 않았다.
- 검증 케이스의 `timezone-transition`, `dst`, `true-solar-time` 7건을 파이프라인 출력으로 단언할 수 있다.
  간지 기대값은 여전히 공인 만세력 대조를 기다린다.
- 파이썬 없이 정답지를 다시 뜰 수 있다. 절기와 달리 Node 만 있으면 된다.
- UTC+8:30 시기 정규화는 진태양시를 켠 경로에서 확인했다.
  청목서원 명리보감 사례 둘(1955-08-08 서울, 1956-07-07 부산)을 플러스만세력으로 재조회해
  네 기둥이 모두 같았고 우리 엔진도 같은 값을 낸다. 1956년 사례는 절입 여유가 2분이라 30분을 잘못 다루면 월주가 갈린다.
  진태양시를 끈 경로는 확인하지 못했다. 무보정 관행은 기록 시계를 그대로 쓰므로 30분이 갈릴 수 있고,
  그 경우 `era-normalization-divergence` 로 화면에 알린다.
