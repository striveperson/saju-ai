> 공인 만세력 대조를 거친 사주 계산 기대값을 둔다.

케이스는 [`cases.ts`](cases.ts) 에 있고 불변식은 [`cases.test.ts`](cases.test.ts) 가 검사한다.

JSON 이 아니라 타입이 붙은 TS 모듈이다. 기대값 필드가 엔진 출력 타입과 어긋나면 `tsc` 가 잡는다.
`Pillar` 를 `` `${HeavenlyStem}${EarthlyBranch}` `` 로 두었으므로 오타는 컴파일에서 걸린다.

## 케이스 두 종류

`VerifiedCase` 는 대조를 마쳤다. `expected` 가 채워져 있고 `sources` 가 비어 있지 않다.
회귀 테스트가 이 케이스의 기대값을 단언한다.

`PendingCase` 는 아직이다. `expected` 는 `null` 이고 `blockedBy` 에 무엇이 있어야 확정되는지 적는다.
타입이 갈라져 있어 기대값을 반쯤 채운 채 `verified: true` 를 붙일 수 없다.

기대값을 추측해 채우지 않는다. 채우려면 대조 출처가 먼저 있어야 한다.

## 확정하는 방법

1. 공인 만세력 두 곳 이상에서 같은 값을 확인한다
2. `expected` 를 채우고 `verified` 를 `true` 로 바꾼다
3. `sources` 에 대조한 만세력과 조회 일시를 남긴다
4. `blockedBy` 를 지운다
5. 유파가 갈리는 지점이면 `notes` 에 어느 유파를 따랐는지 적는다

## 일주 앵커

일주 계산의 기준 앵커 값은 문서나 코드에 근거 없이 하드코딩하지 않는다.
`requirement: 'anchor'` 이면서 `verified: true` 인 케이스 3개 이상으로 확정한다.

지금 그 조건을 만족하는 케이스는 0개다. 앵커 후보 셋(`anchor-20000101`,
`anchor-19840217`, `anchor-19350620`)이 전부 대조 대기 상태다.

기준 케이스(1995-01-27 무오일)에서 60갑자를 돌려 세 값을 역산할 수는 있다.
그렇게 채우지 않는다. 앵커에서 나온 값으로 앵커를 검증하는 순환 논증이라 아무것도 증명하지 못한다.
세 케이스는 각각 독립적으로 대조해야 한다.

## 필수 경계 목록과의 연결

각 케이스에 `requirement` 태그가 붙어 있다.
`cases.test.ts` 가 `Requirement` 의 모든 값에 케이스가 하나 이상 있는지 검사한다.
목록에 있는데 케이스가 없으면 그 경계는 아무도 검사하지 않는 상태로 남으므로 테스트가 실패한다.

태그 하나에 케이스가 있다는 것이 그 경계를 검증했다는 뜻은 아니다.
대조를 마쳤는지는 `verified` 가 말한다.

## 원본에서 옮기지 않은 것

기준 케이스의 `support_ratio: 0.875` 를 옮기지 않았다.
[ADR 0007](../../../../../../docs/adr/0007-strength-five-grade-model.md) 이 대체한
8단계 방조 비율 모델의 필드다. 지금 모델은 득령, 득지, 득시, 득세 네 불리언과
5등급이고 비율을 쓰지 않는다.
