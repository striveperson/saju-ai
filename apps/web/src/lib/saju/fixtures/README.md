# 검증 케이스

> 공인 만세력 대조를 거친 사주 계산 기대값을 둔다.

케이스는 [`cases.ts`](cases.ts) 에 있고 불변식은 [`cases.test.ts`](cases.test.ts) 가 검사한다.

JSON 이 아니라 타입이 붙은 TS 모듈이다. 기대값 필드가 엔진 출력 타입과 어긋나면 `tsc` 가 잡는다.
`Pillar` 를 `` `${HeavenlyStem}${EarthlyBranch}` `` 로 두었으므로 오타는 컴파일에서 걸린다.

표준시 도입 이전이다.

같은 작업에서 대조를 마친 케이스 여섯을 더했다. 출처는 청목서원 명리보감 사례이고
플러스만세력으로 재조회해 네 기둥이 모두 같은 것을 확인했다.
그중 둘이 UTC+8:30 시기라 표준시 정규화를 검증한다.
`verified-19560707-busan` 은 소서 절입 여유가 2분이라 30분을 잘못 다루면 월주가 갈린다.

시주를 구현하면서 자시 경계 네 건을 확정했다. 포스텔러 만세력에 서울을 넣어 네 건을
정자시로 조회하고, 정책이 실제로 갈리는 두 건은 야자시로 한 번 더 받았다.
일진은 uncle.tools 달력으로 따로 받았다.
네 건이 이틀 안에 몰려 있어 년주와 월주가 같고 일주와 시주만 갈린다.

진태양시 보정은 옵션이 아니라 항상 적용된다(ADR 0016).
`CaseInput.options` 에 `trueSolarTime` 이 없고 `longitude` 가 그 자리를 대신한다.

`timezone-transition` 과 `dst`, `wall-clock-ambiguity`, `pre-standard-time` 케이스는
간지 기대값이 비어 있어도 파이프라인 출력은 검증된다.
`time.test.ts` 와 `cases.test.ts` 가 입력만 가져다 보정 결과와 구간 분류를 단언한다.
tz database 로 결정되는 값이라 공인 만세력을 기다릴 이유가 없기 때문이다.
간지 기대값은 여전히 대조를 기다린다.

## 케이스 두 종류

`VerifiedCase` 는 대조를 마쳤다. `expected` 가 채워져 있고 `sources` 가 비어 있지 않다.
회귀 테스트가 이 케이스의 기대값을 단언한다.

`PendingCase` 는 아직이다. `expected` 는 `null` 이고 `blockedBy` 에 무엇이 있어야 확정되는지 적는다.

기대값을 추측해 채우지 않는다. 채우려면 대조 출처가 먼저 있어야 한다.

### 기둥은 하나씩 확정된다

`expected` 의 네 기둥은 전부 선택 항목이다. 기둥마다 독립 출처가 다르기 때문이다.

| 기둥 | 독립 출처                                                      |
| ---- | -------------------------------------------------------------- |
| 일주 | KASI 음양력 API 의 일진. 단 아래 예외가 있다                   |
| 년주 | 없다. KASI 세차는 음력 설날 기준이라 사주의 입춘 기준과 다르다 |
| 월주 | 없다. KASI 월건은 음력월 기준이라 절기월과 다르다              |
| 시주 | 없다                                                           |

KASI 세차를 그대로 쓰면 매년 입춘과 설날 사이 한 달 남짓한 구간에서 년주가 틀린다.
그래서 앵커처럼 일주만 검증하는 케이스는 일주만 채운다.
근거 없이 채우느니 비워 둔다. 최소 한 기둥은 있어야 하고 테스트가 검사한다.

일주의 예외는 보정이 날짜 귀속을 옮기는 케이스다.
일진은 날짜당 간지를 주는 것이지 어느 출생이 어느 날짜에 속하는지를 정해 주지 않는다.
그 귀속은 진태양시 보정과 야자시 정책이 정하므로 검증 대상이 곧 대조 기준이 된다.
자시 경계 네 건이 여기 해당하고, `expected.day` 는 만세력 한 곳에 기댄다.

## 확정하는 방법

1. 값을 확인한다. 기둥마다 필요한 출처 수가 위 표에서 갈린다.
   독립 출처가 있는 기둥은 공인 만세력 두 곳 이상, 없는 기둥은 한 곳이다
2. `expected` 를 채우고 `verified` 를 `true` 로 바꾼다
3. `sources` 에 대조한 만세력과 조회 일시를 남긴다.
   출처가 확인해 준 범위가 기대값보다 좁으면 그 사실을 함께 적는다
4. `blockedBy` 를 지운다
5. 유파가 갈리는 지점이면 `notes` 에 어느 유파를 따랐는지 적는다

## 일주 앵커

일주 계산의 기준 앵커 값은 문서나 코드에 근거 없이 하드코딩하지 않는다.
`requirement: 'anchor'` 이면서 `verified: true` 인 케이스 3개 이상으로 확정한다.

조건을 채웠다. 셋 다 KASI 음양력 API 의 일진으로 대조했다.

| 케이스            | 날짜       | 일진 | 율리우스 적일 |
| ----------------- | ---------- | ---- | ------------- |
| `anchor-20000101` | 2000-01-01 | 무오 | 2451545       |
| `anchor-19840217` | 1984-02-17 | 신사 | 2445748       |
| `anchor-19350620` | 1935-06-20 | 정묘 | 2427974       |

기준 케이스(1995-01-27, 적일 2449745, 무오)까지 넷이 하나의 식으로 재현된다.

```
일주 간지 인덱스 = (율리우스 적일 + 49) mod 60
```

기준 케이스에서 60갑자를 돌려 역산하지 않았다.
앵커에서 나온 값으로 앵커를 검증하면 순환 논증이라 아무것도 증명하지 못한다.
KASI 는 포스텔러와 다른 독립 출처다.

셋 다 정오 출생이라 야자시 정책이 개입하지 않는다.
`anchor-20000101` 은 기준 케이스와 정확히 1800일(60의 30배) 떨어져 있어 60갑자 잔여가 같다.
공식을 새로 제약하지는 않고 윤년 계산만 확인한다.

## 필수 경계 목록과의 연결

각 케이스에 `requirement` 태그가 붙어 있다.
`cases.test.ts` 가 `Requirement` 의 모든 값에 케이스가 하나 이상 있는지 검사한다.
목록에 있는데 케이스가 없으면 그 경계는 아무도 검사하지 않는 상태로 남으므로 테스트가 실패한다.

태그 하나에 케이스가 있다는 것이 그 경계를 검증했다는 뜻은 아니다.
대조를 마쳤는지는 `verified` 가 말한다.

## 원본에서 옮기지 않은 것

기준 케이스의 `support_ratio: 0.875` 를 옮기지 않았다.
[ADR 0007](../../../../../../docs/adr/0007-strength-five-grade-model.md) 이 대체한
8단계 방조 비율 모델의 필드다. 지금 모델은 득령, 득지, 득시, 득세 네 불리언과
5등급이고 비율을 쓰지 않는다.
